## 6. Bug thật bắt được (đều do chạy thật, không do đọc code)

| # | Bug | Triệu chứng | Sửa |
|---|---|---|---|
| 1 | Same-origin allowlist tính từ **port cấu hình** | Với port 0, OS chọn port khác ⇒ mutation cùng origin bị 403 | `serve` cập nhật `bind` thành địa chỉ **đã bind** trước khi dựng state |
| 2 | Writer lock chưa nhả trước khi trả response | Request mutation kế tiếp có thể gặp `WriterLocked` ⇒ **reply rỗng**, flake 8/8 | `admit_input` giữ một `Arc` riêng và `close()` **trước** khi trả response |
| 3 | Client test gửi `Connection: close` | Trên Windows, reset có thể tới **trước** byte của reply ⇒ client đọc 0 byte | Bỏ header đó khỏi request; client đọc tới `Content-Length` khai báo, và retry nếu reset khi reply chưa đủ |

Bug 3 là bài học đáng ghi: server log **đã trả lời đủ** (`responding 200 OK`, `connection closed cleanly`) trong khi
client đọc 0 byte. Không có log của server thì rất dễ "sửa" nhầm phía server.

## 11. Follow-up audit M10 (23/09/2026)

A33/API follow-up đã sửa các lỗ hổng boundary được audit thấy: mutation bắt buộc Host loopback và Origin hợp lệ (thiếu Origin bị từ chối kể cả token đúng); cursor không phải số trả 400; đọc journal dùng page có trần và lỗi store không bị đổi thành state rỗng; SSE theo dõi event mới sau khi stream mở, heartbeat không giả làm tiến độ, và client chậm bị ngắt ở giới hạn buffer để reconnect bằng cursor bền. Request body bị giới hạn 64 KiB, body quá cỡ được drain có trần rồi trả 413. Acceptance A33 xác nhận request quá cỡ không tạo input và live event tới stream đã mở.

Raw HTTP acceptance client nay retry tối đa ba lần **chỉ** khi peer không trả response hoàn chỉnh; mọi retry giữ nguyên request ID/payload, nên POST vẫn dedupe qua store và một lỗi HTTP thật không bị retry. A33 passed **6/6** lần liên tiếp sau sửa transport. `ci.yml` hiện có matrix milestone M0–M12 **trên Windows**; không còn đúng khi nói M10 vắng khỏi CI. Linux vẫn pending theo yêu cầu hiện tại.
