## Ranh giới P1 đã bàn giao

- `harness-store-sqlite` sở hữu điều phối SQLite một connection, migration 1 giao dịch, WAL/FULL, busy timeout có giới hạn, writer lock đa process, host generation, task lease, records event/inbox/instruction/projection/source-work, snapshot, artifact đã flush, synthetic receipt và plugin metadata bền vững.
- `harness-session` sở hữu admission command có kiểu, fold event xác định, giữ raw instruction `unclassified`, khôi phục snapshot cộng journal tail, chẩn đoán corruption và ranh giới pending intent không có runtime.
- `harness-kernel` sở hữu validation graph service bắt buộc/tùy chọn, lookup scope gần nhất, undo registration chính xác, lease theo generation, rollback/join resource, drain khi provider mất và shutdown report có thứ tự dùng chung.
- `harness-cli` nối các lệnh metadata (`init`, `sessions list`, `status`, `plugins list`, `plugins inspect`, `config explain`) và child host chỉ dành cho fixture process thật.
- `harness-types` thêm P1 IDs và lỗi storage/kernel dạng máy đọc được ổn định, không đổi ý nghĩa schema P0.

P1 **không** làm model/LLM loop, context hoặc compaction, coding tools/process execution, memory extraction/FTS hay Tencent adapter, multi-agent scheduler, external plugin loading, release/deployment hoặc Web UI. Synthetic receipt và child host là fixture, không phải execution production.

## Ghi nhận red/green và negative controls

Lần compile test P1 đầu tiên cố ý fail tại interface vì các implementation mới `PluginGraph`, `SessionService`, `SqliteStore` chưa tồn tại. Sau implementation, 20/20 pass. Gate P1 đầu tiên cũng fail closed vì resolver dùng Cargo target `p1`; verifier đã sửa thành target thật `phase_p1`, rồi gate đầy đủ pass. Phase tests còn assert đường lỗi migration, admission, receipt, read-only, snapshot corruption, unknown critical event, lease, stale fence, rollback và shutdown trên component thật.

## Ownership, dependency và platform

Các path sở hữu là ba crate P1 mới, CLI/fixture/test P1, shared IDs/errors P1, acceptance registry và phase verifier, root Cargo manifest/lockfile, cùng SPEC/evidence/handoff P1 song ngữ. Không ghi đè thay đổi user không liên quan.

Dependency P1 được pin là `sqlx 0.9.0` (bundled SQLite, Tokio runtime, migrations, UUID), `tokio 1.53.1`, `fs2 0.4.3`, `tempfile 3.27.0` và `proptest 1.11.0`; các pin P0 còn nguyên. Môi trường đã kiểm chứng là Rust/cargo 1.97.1, target `x86_64-pc-windows-msvc`, PowerShell 7.6.5 trên Windows.

Chưa chạy Linux, GitHub Actions, đóng gói release hay deployment trong assignment này. Workflow repo vẫn là khai báo remote P0; không có quyền push. Fault injection xác định chứng minh rollback transaction tại boundary đã đặt tên nhưng không giả lập hết disk vật lý/hardware failure. Đây là giới hạn được báo rõ, không phải acceptance pass.

## Ranh giới nghiệm thu và phase tiếp

P1 đã xanh cục bộ và sẵn sàng user nghiệm thu, nhưng chưa publish hoặc activate. Bước an toàn tiếp theo là review evidence/handoff này, rồi quyết định rõ về commit/push. Không bắt đầu P2 trước khi P1 được nghiệm thu và có assignment/SPEC P2 riêng.
