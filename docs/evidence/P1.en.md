## Delivered P1 boundary

- `harness-store-sqlite` owns one-connection SQLite coordination, transactional migration 1, WAL/FULL durability settings, bounded busy timeout, a cross-process writer lock, host generations, task leases, event/inbox/instruction/projection/source-work records, snapshots, flushed artifacts, synthetic receipts, and persisted plugin metadata.
- `harness-session` owns typed admission commands, deterministic event folding, raw `unclassified` instruction retention, snapshot-plus-tail recovery, corruption diagnostics, and the no-runtime pending-intent boundary.
- `harness-kernel` owns required/optional service graph validation, scoped nearest lookup, exact registration undo, generation-bound service leases, resource rollback/join, provider-loss drain, and shared ordered shutdown reports.
- `harness-cli` exposes persisted metadata operations (`init`, `sessions list`, `status`, `plugins list`, `plugins inspect`, `config explain`) and a fixture-only child host used for real process termination tests.
- `harness-types` adds P1 IDs and stable machine-readable storage/kernel errors without changing P0 schema meanings.

P1 deliberately does not implement an LLM/model loop, context building or compaction, coding tools/process execution, memory extraction/FTS or Tencent adapters, multi-agent scheduling, external plugin loading, release/deployment, or Web UI. Synthetic receipts and the child host are test fixtures, not production execution.
