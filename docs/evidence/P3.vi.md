P3 giữ nguyên schema P0/P1/P2, single durable writer, fencing task/session, provider request frozen và quy tắc P2 runtime không tự execute tool.

## Ranh giới đã bàn giao

- `crates/harness-tools` là execution boundary duy nhất của P3. Crate này sở hữu coding action/provider schema có version, policy transform, approval explicit, workspace identity canonical, file/list/search/patch rooted, process structured và shell explicit, Git inspection, task update scoped, receipt/view immutable và reconciliation sau restart.
- `harness-store-sqlite` thêm tools schema revision theo kiểu additive. Issue/revoke/consume approval, register/reassociate project, tool intent, settlement, artifact scope, event/projection, sequence marker và fault point đều qua single writer hiện có.
- `harness-types`, `harness-session`, `harness-providers` và `harness-runtime` thêm P3 ID/error ổn định, fold pending/unknown khi recovery, tool schema/provider tool call đã normalize và coding-loop adapter một chiều P2→P3. Provider argument chưa hoàn chỉnh dừng trước intent.
- `harness-cli` thêm `code capabilities --json` và `code fixture` xác định, không cần key, chạy response P2 thật qua search, patch được approve, verification, receipt persist và inspect state sau restart. Không cần credential live.
- Registry acceptance, phase verifier, CI matrix, SPEC song ngữ và evidence/handoff này xác định phase boundary. Không bao gồm P4 memory extraction, P5 scheduling/delegation, P6 plugin, P7 release/deployment hay P8 Web UI.

## Platform và giới hạn verification

Local verification chạy trên Windows với Rust `1.97.1`, Cargo `1.97.1`, PowerShell `7.6.5` và Git `2.55.0.windows.2`. Host báo cleanup cây process bằng Windows Job Object, không có strict isolation hay filesystem/network sandbox. Gate P3 Ubuntu remote cũng đã pass nhánh process-session POSIX.

Chưa dùng DeepSeek credential thật, chưa gọi API trả phí, external provider smoke, deployment, production activation, release package, P4 semantic memory extraction, P5 multi-agent scheduler, plugin, browser hay Web UI. Môi trường này không có `cargo-llvm-cov`, `cargo-mutants`, `cargo-audit`, nên không claim coverage, mutation hay audit. Trạng thái remote CI được ghi trong handoff cuối sau push; local PASS không phải claim production activation.

Phase dừng ở P3. Đọc [P3 restart handoff](../handoffs/P3.vi.md) trước công việc mới; không bắt đầu P4 nếu chưa có assignment và gate riêng.
