## Delivered P0 boundaries

- Rust 1.97.1 workspace with `harness-types` and `harness-cli`; lockfile, toolchain pin, and narrow local-runtime `.gitignore` are present.
- Public `ha` supports only help, version, and strict TOML config validation. It has no provider, credential, network, model, session, tool, memory, or orchestration surface.
- Versioned typed contracts, strict UUIDv7 IDs, explicit authority, typed errors, `harness-json-v1` SHA-256 hashing, JSON Schema generation, static continuation fixture verification, P0 acceptance registry, fail-closed PowerShell gate, and Windows/Linux CI declaration are present.
- P0 does not implement C01–C30, K01–K14, R01–R12, W01–W06, persistence, recovery runtime, plugins, multi-agent execution, Web API, or UI. Their registry entries remain `not_implemented` where applicable.

The accepted boundary decision is recorded in [ADR-0001](../adr/ADR-0001-P0-FOUNDATION-BOUNDARIES.en.md).

## Manual defense mutations

Each mutation was applied temporarily to a real component, caused its named real test to fail, then was restored before subsequent checks.

| Guard weakened temporarily | Required detector | Observed result |
|---|---|---|
| UUID nil/version rejection removed | `invalid_ids_versions_sequences_authorities_payloads_and_hashes_are_rejected` | Failed: nil UUID was accepted. |
| `schema_version == 1` changed to allow `0` | same contract-boundary test | Failed: version 0 was accepted. |
| Float rejection replaced with canonical `0` | `canonical_hash_is_deterministic_and_rejects_floating_point` | Failed: decimal input returned bytes instead of `invalid_payload`. |
| `HarnessConfig` unknown-field denial removed | `p0_f02_cli_rejects_unknown_config_and_option_inputs` | Failed: unknown config field exited successfully. |
| Duplicate input detection disabled | `p0_f06_continuation_fixture_is_complete_without_a_projector` | Failed: fixture integrity reported the missing duplicate detection. |

Two exploratory changes (removing only the nil branch, then only the UUIDv7 branch) did not make the existing combined boundary test fail because the remaining predicate still rejected that particular fixture input. They were restored immediately and are not counted as successful mutation evidence; the five rows above are the effective defense mutations.

## Dependencies, CI, and known limits

The lockfile pins `serde`, `serde_json`, `schemars`, `thiserror`, `sha2`, `uuid`, `clap`, and `toml` at the exact versions approved in the SPEC. Direct dependency licenses/MSRV were checked from crates.io before resolution and the local toolchain was Rust/cargo 1.97.1 on `x86_64-pc-windows-msvc` with PowerShell 7.6.5.

`.github/workflows/ci.yml` declares the same P0 gate for Windows and Linux with no credential step. For initial commit `e05d18c`, documentation checks and Ubuntu P0 gate passed, while Windows failed only P0-F03 because Git checked in schemas as CRLF but the Rust generator emits LF. `.gitattributes` now pins `schemas/*.json` to LF and P0-F03 asserts that policy; the CI rerun is mandatory and still pending. No coverage or third-party mutation/audit tool was installed; the manual mutations above supplement real component tests but do not replace future coverage/security work.

## Acceptance boundary

P0 has completed its local acceptance gate but requires a successful Windows/Linux CI rerun and user acceptance. Do not assign P1 before both conditions. P0 alone must not be represented as durable session recovery or multi-agent functionality.
