## 2. Ownership and contracts

[docs/specs/P7.en.md](../specs/P7.en.md) records scope, dependencies, the failure
model and the pinned contracts; the runbook is
[docs/implementation/P7_RELEASE.en.md](../implementation/P7_RELEASE.en.md).

`crates/harness-maintenance/` is new and owns the release matrix, backup manifests,
restore validation, migration safeguards, retention classes, tombstones and
artifact garbage collection. It composes `harness-store-sqlite`,
`harness-memory` and `harness-session`; it is **not** a second database authority,
and every durable write still goes through the existing P1 transaction coordinator
and host fence.

Additive changes elsewhere:

- `harness-store-sqlite` gained `src/store/maintenance.rs` with a **new, additive**
  migration table `maintenance_schema_migrations` (revision 1) and the tables
  `maintenance_tombstones`, `maintenance_journal` and `maintenance_pins`. No
  existing revision was edited. It also gained `publish_artifact_recorded`, which
  commits artifact bytes and the row that makes them reachable together, and
  `all_schema_revisions`, which reads every surface's revision for a migration
  decision.
- `harness-types` gained the P7 codes `backup_manifest_invalid`,
  `restore_target_conflict` and `retention_refused`; every refusal named in this
  document is one of them plus the existing P0/P1 codes.
- `harness-cli` gained `ha maintenance doctor|backup|verify-backup|restore|retain|tombstones|gc|migrate-copy|release-matrix`.
  The maintenance operations ship as subcommands of one command group; the
  operator guides document that shipped form.

P7 pinned these contracts before implementing them:

| Contract | Value |
|---|---|
| `MAINTENANCE_CONTRACT_VERSION` | 1 |
| `BACKUP_MANIFEST_NAME` | `backup-manifest.json` |
| `BACKUP_DATABASE_NAME` | `harness.sqlite3` |
| `DEFAULT_GC_GRACE_SECONDS` | 604800 (7 days) |
| Maintenance schema revision | 1, additive |

No new external dependency was added: the snapshot uses `SQLite`'s own
`VACUUM INTO` through the already-pinned `sqlx`, and everything else reuses
workspace dependencies already in `Cargo.lock`.

Three scope decisions are worth stating explicitly, because each one is a place
where a weaker implementation would have passed a thinner test:

1. **`invalidate` is not `delete`.** Invalidation marks derived knowledge unusable
   and keeps the historical record; archiving moves content out of active use while
   keeping it restorable; only `forget` removes content, and only `forget` requires
   confirmation and writes a tombstone.
2. **A restore never activates.** It writes a fresh directory, records
   `restore.json` with `"activated": false`, and stops. Activation is a separate
   explicit action (`activate_restored`), which the acceptance target exercises
   only after inspecting the restored copy.
3. **A store newer than the binary is refused for writes, not rewritten.** The
   recorded revision is compared on every surface, and read-only inspection stays
   available so an operator can diagnose the directory instead of damaging it.

## 4. Fault windows and negative controls asserted

- `p7_s02...` proves the manifest is a contract rather than a note: an existing
  backup directory is refused rather than merged, a manifest whose body was edited
  after its digest was computed is refused, an artifact whose bytes changed is
  refused even after the manifest digest is repaired, a missing artifact is refused,
  and a directory holding no store is refused instead of producing an empty backup.
  The pins active at backup time appear in the manifest and in the outcome.
- `p7_c27...` proves a restore cannot damage anything: restoring into the backup
  directory itself, into a populated destination or over a live store is refused
  with `restore_target_conflict`; a snapshot whose database does not match its
  manifest hash is refused with `backup_manifest_invalid`; the restored directory
  carries `"activated": false` and no `.active` marker; the source directory is
  byte-for-byte untouched, checked by reopening it read-only afterwards; and
  activation is a separate call that is the only thing that writes `.active`.
- `p7_s03...` proves an upgrade cannot corrupt a store: the source database is read
  before and after `migrate_copy` and compared byte-for-byte, the copy is opened
  read-only and holds the same records, an occupied destination and a storeless
  source are refused, and a store whose recorded revision is 99 is reported as
  `TooNew { recorded: 99, supported: 1 }` with `is_writable() == false` while
  read-only inspection succeeds and `open_writer` fails with a typed
  `unsupported_schema_version`-class error.
- `p7_s04...` proves the retention classes are genuinely separate: `invalidate`
  and `archive` run without confirmation, leave no tombstone and do not tombstone
  an unrelated source; `forget` with a wrong or empty confirmation is refused with
  `retention_refused` and leaves no tombstone behind; an empty target is refused
  with `invalid_payload`; and the successful forget records the reason and the
  declared surviving copies.
- `p7_c28...` proves a forget is durable and disclosed: after the forget,
  re-extraction is refused and `is_tombstoned` is true; the tombstone names every
  declared surviving copy, which the `retention_summary` an operator reads repeats;
  an unrelated source remains extractable; and after a real backup and restore the
  tombstone is still present, still refuses re-extraction and still names the same
  surviving copies, so a restore cannot resurrect forgotten data.
- `p7_gc_never_removes_a_pinned_artifact` proves the backup/collection race is
  closed: a dry run reports the artifact as collectable and deletes nothing; an
  artifact inside the grace period is retained as young with zero bytes reclaimed;
  with no grace period at all a pinned artifact is retained as pinned, keeps its
  bytes and keeps its record, and a backup taken while pinned records the pin; after
  the pin is released the artifact is collected for real, its bytes are gone, its
  record is gone, and a second pass considers nothing.
- `p7_s01...` proves the release matrix cannot hide a problem: a platform with
  empty evidence, a matrix with no platforms and a matrix with a future schema
  version are each refused; a benchmark with no measurement reports `met() ==
  None`; a measurement of 900 ms against a 250 ms target reports `met() ==
  Some(false)` while 1200 ms against 2000 ms reports `Some(true)`; a `failing`
  platform makes the verdict "not release-ready" and an `unverified` platform makes
  it "partially verified"; and the 44 cases are expanded rather than summarised.
- `p7_s06...` proves the packaged binary is a real artifact: it starts, reports a
  version, exposes every documented maintenance subcommand, diagnoses a real data
  directory (`writable: true`, 1 session, 1 artifact, schema revision 1, 0
  tombstones) while listing three things it did **not** verify, reports both
  platforms with 44 verified cases and `measured: null` for every benchmark, and
  reflects a supplied measurement back — 900 ms reported as missing a 250 ms target
  and 1200 ms reported as meeting a 2000 ms one.
- `p7_s07...` proves the documentation is bound to the binary: both operator
  guides exist, link to each other in both directions, document every shipped
  subcommand and the manifest file name, state that a restore does not activate on
  its own and that there is no daemon, and every documented subcommand is checked
  against the real `maintenance --help` output.

## 6. RED history and confidence

RED was observed for real defects rather than only for missing APIs:

- `publish_artifact` wrote artifact bytes but never inserted the `artifacts` row,
  so a backup taken from a store that had only ever published through that path
  pinned **zero** artifacts. The fix added `publish_artifact_recorded`, which
  commits the bytes and the row in one transaction, and the backup now checkpoints
  the write-ahead log before `VACUUM INTO` so a row that is still only in the WAL
  cannot be missing from the snapshot.
- `sqlx::query` refuses dynamically built SQL (`SqlSafeStr` is not implemented for
  a `String`), so `VACUUM INTO` could not be bound as a parameter. The literal is
  built after refusing a NUL byte or a newline in the destination path and doubling
  embedded quotes, and the audit assertion is made explicitly through
  `AssertSqlSafe` rather than silently swallowed.
- The migration guard checked only the `store` revision, so a store with a newer
  `runtime`, `tools`, `memory`, `delegation` or `maintenance` revision would have
  been reported writable. `check_store_compatibility` now compares every surface
  and names the one that is too new.
- The first version of the backup test asserted that the restored copy had no
  `writer.lock`. The real invariant is that the lock is not *copied*: it is an OS
  advisory lock, so the migration open creates its own empty lock file. The
  assertion was corrected to check that the copy's lock is empty and that the copy
  is genuinely writable — the behaviour is stronger than the original assertion
  assumed, and the test now states it correctly.
- The registry coverage assertion initially required every test name to be
  target-qualified. The registry deliberately names same-target tests
  unqualified and qualifies only cross-target entries, so the assertion was
  replaced with one that checks the unqualified names against the case's own
  target file and the qualified ones against a module that exists.
- The first version of `p7_s05...` checked for `tests/phase_p1.rs` relative to the
  repository root, which does not exist; the acceptance targets live under
  `crates/harness-cli/tests/`. The check now resolves each target in the crate
  that owns it.
- On Windows, canonicalising the repository root yielded a `\\?\` verbatim path,
  which made the real filesystem checks fail on files that exist. The path helper
  now keeps the plain relative form the filesystem checks expect.

Every fix was in implementation or in the test's own model of the contract; no
assertion was weakened and no fixture expectation was edited to make an
implementation pass.
