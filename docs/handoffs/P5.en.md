## 4. P5 surfaces P6 must not bypass

- Spawn entry point: `harness_orchestrator::WorkerScheduler::dispatch` plus the
  `WorkerBackend` trait. A new worker kind must go through it so budgets, depth
  and drain semantics still apply.
- Authority propagation: `TaskBrief.grants` is host-authored and
  `DelegationGrants::intersect` can only narrow. A role name still grants
  nothing, and a child must never obtain broader authority than its parent.
- Scoped memory: `DelegatedMemoryService::bind_at_spawn` and
  `validate_before_dispatch` are the only supported way to give a worker memory.
  A binding pinned to an older revision is reported `Stale` and must be rebuilt.
- Recovery fixtures: `p5_c11...`, `p5_c25...`, `p5_s06_recovery...` and
  `p5_s04_worktree_lifecycle_is_durable` are the cross-agent recovery baseline.

## 5. Known limitations

Worktrees isolate concurrent edits and are explicitly not a security boundary.
Background execution after CLI exit, a daemon, remote workers and a marketplace
remain out of scope. Editing delegation refuses a dirty repository input and
never stashes or resets user changes. Semantic memory is never the authority for
whether a task completed.
