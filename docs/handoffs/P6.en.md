## 4. P6 surfaces P7 must not bypass

- Transport and handshake: `harness_extensions::ExtensionTransport` with
  `ExtensionHandshake` and `NegotiatedSession`. The pinned bounds
  (`EXTENSION_PROTOCOL_VERSION = 1`, `MAX_FRAME_BYTES = 1 MiB`,
  `MAX_STDERR_BYTES = 64 KiB`, `MAX_INFLIGHT_CALLS = 4`, `HANDSHAKE_TIMEOUT_MS = 5000`,
  `DEFAULT_CALL_TIMEOUT_MS = 30000`, `MAX_SKILL_BYTES = 256 KiB`) may not be
  raised silently. An oversize frame is a protocol error, stdout carries protocol
  frames only, and a call whose response never arrives stays uncertain instead of
  becoming a synthesized success.
- Trust: `TrustGrant` is principal-pinned, digest-pinned and capability-scoped,
  and `ExtensionRuntime::load` must stay the only entry point that starts a
  process. A grant can only narrow through `intersect`, never widen. Nothing may
  start an executable or resolve a secret without an explicit user-level grant,
  and a plugin process may only see `ENVIRONMENT_ALLOWLIST` plus explicit
  overrides.
- Host method surface: `HOST_METHOD_ALLOWLIST` — `host.echo`,
  `host.workspace.observe`, `host.task.read`, `host.memory.search`. A requested
  method outside it is refused with `HostMethodDenied`; do not add methods to the
  allowlist as a convenience.
- Policy gate: external tools execute only through
  `harness_tools::ToolExecutionService::prepare` and `execute` with
  `CodingToolAction::ExternalTool` and the `ExternalToolDispatcher` hook, which
  sits after the durable intent commit. There is no second authorization path,
  and a nested call keeps the parent invocation id for correlation.
- Lifecycle and generations: registrations go through
  `harness_kernel::ScopedRegistry`. Unload/reload is generation-bound, so a late
  disposer from an older generation cannot remove the replacement, and remounting
  never authorizes repeating a side effect.
- Skills: `discover_skills`, `compose_skills` and `SkillVersionPin`. Skill content
  is data and cannot mint tool permissions; a skill update becomes visible only at
  a recorded boundary, and skill text reaches context only through the P2 context
  builder.
- MCP: `harness_extensions::McpClient`. MCP negotiation belongs to the official
  SDK contract and is never assumed compatible with the custom plugin protocol; a
  schema change requires renegotiation before use, and MCP tools cross the same P3
  gate with scoped registration.
- CLI: `ha extensions inspect|capabilities|register|skills` is the only supported
  local registration surface. `register --confirm` with a trust file is what
  activates anything; inspection alone starts no process.

## 5. Known limitations

Transport isolation is a bounded protocol plus a minimal environment and an
allowlisted method surface, explicitly **not** OS sandboxing of untrusted native
code. Remote MCP endpoints are out of scope, as are marketplace, Wasm, arbitrary
native dynamic loading and external loop or storage plugins. Mutation testing,
coverage, advisory audit and a broad secret scan were not run because the tooling
is not installed. One external dependency was added (`rmcp =3.4.0`, Apache-2.0)
and no advisory status is claimed for it. Only local gate results are recorded
unless noted, and this work is self-verified with no independent agent.
