## Quy trình khởi động lại

1. Đọc handoff này, [evidence P1](../evidence/P1.vi.md), [SPEC P1](../specs/P1.vi.md) và các contract kiến trúc được link trước khi sửa.
2. Chạy `git status --short` và `git diff --check`; giữ nguyên mọi thay đổi P1-owned và thay đổi user không liên quan.
3. Chạy `cargo fmt --all -- --check` và `cargo clippy --workspace --all-targets --locked -- -D warnings`.
4. Chạy `cargo test --workspace --all-targets --locked`, `cargo test -p harness-cli --test phase_p0 --locked -- --test-threads=1` và `cargo test -p harness-cli --test phase_p1 --locked -- --test-threads=1`.
5. Chạy `pwsh -NoProfile -File scripts/Verify-Phase.ps1 -Phase P1 -SelfTest`, `pwsh -NoProfile -File scripts/Verify-Phase.ps1 -Phase P1 -Json` và `pwsh -NoProfile -File scripts/Verify-Phase.ps1 -Phase P0 -Json`.
6. Chạy `pwsh -NoProfile -File scripts/Verify-Docs.ps1 -SelfTest`. Nếu fail, chỉ sửa path P1/documentation sở hữu rồi chạy lại gate liên quan; không bypass guard hoặc bắt đầu P2.

## Guardrail contract và khoảng trống đã biết

- Giữ nguyên schema P0 version 1, ID format, authority label, canonical hash rule và nghĩa fixture cũ. Thay đổi không tương thích cần SPEC/ADR mới được review.
- SQLite transaction coordinator là durable writer duy nhất. Không thêm store authority thứ hai, ACK trước commit hoặc coi observer notification là persistence.
- Synthetic receipt không chứng minh tool execution P3. P1 chưa có model call, shell/process side effect, memory extraction, Tencent adapter, multi-agent scheduling, external plugin process, Web UI, backup/schema upgrade flow hay production activation.
- Fault plan là boundary test xác định, không phải bảo đảm hết disk vật lý. Linux và remote CI chưa chạy trên revision chưa push này.
