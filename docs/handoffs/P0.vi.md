## Quy trình khởi động lại

1. Xác nhận checkout vẫn chỉ có thay đổi P0-owned, không có user edit chưa review: `git status --short` và `git diff --check`.
2. Đọc P0 SPEC, handoff này và evidence trước khi đổi source.
3. Chạy `cargo fmt --all -- --check` và `cargo clippy --workspace --all-targets --locked -- -D warnings`.
4. Chạy `cargo test --workspace --locked`, sau đó `cargo run -p harness-types --bin generate_schemas --locked` và xác minh nếu có thay đổi thì chỉ là chín schema files mong đợi.
5. Chạy `pwsh -NoProfile -File scripts/Verify-Phase.ps1 -Phase P0 -SelfTest` và `pwsh -NoProfile -File scripts/Verify-Phase.ps1 -Phase P0 -Json`.
6. Chạy `pwsh -NoProfile -File scripts/Verify-Docs.ps1 -SelfTest`. Nếu check nào fail, chỉ sửa P0-owned paths rồi chạy lại gate; không khởi động P1 để lách lỗi.

## Contract và scope guardrails

- Không đổi âm thầm `schema_version = 1`, ID format, authority labels hay canonical-hash number rules. Mọi thay đổi không tương thích cần revision/ADR mới được review.
- Không thêm store, SQLite, provider/model request, tool execution, memory extractor, child-agent runner, Web API/UI, secret handling hay release work vào P0.
- Static fixture chỉ chứng minh fixture integrity, không chứng minh live restart/recovery. C01–C30 và K01–K14 vẫn chưa hiện thực.
- Giữ test double chỉ tại external Cargo child boundary trong gate self-test; contract, CLI, fixture và gate acceptance tests dùng component thật.
