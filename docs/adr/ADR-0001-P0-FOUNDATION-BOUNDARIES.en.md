# ADR-0001 — P0 foundation boundaries

English | [Tiếng Việt](ADR-0001-P0-FOUNDATION-BOUNDARIES.vi.md)

Status: implemented in P0 on 2026-09-10.

## Context

The harness needs durable, reviewable contracts before it can safely persist a session, invoke a model, execute a tool, or delegate work. The architecture deliberately separates the future execution journal, `WorkingState`, and reusable memory. A convenience P0 runtime would blur those ownership boundaries and make later recovery claims unreliable.

## Decision

P0 implements only a Rust workspace, typed/versioned contracts, strict IDs and validation, `harness-json-v1` hashing, schemas generated from real types, a static continuation oracle, a minimal credential-free `ha` CLI, an acceptance registry, and a fail-closed local/CI gate.

The accepted boundary rules are:

- Records accept only `schema_version = 1`; incompatible meanings require a new revision.
- IDs are typed `<kind>_<uuid-v7-lowercase-hyphenated>` values; authority is explicit and never inferred.
- Canonical hashing accepts no floating-point or exponent number. A future real-number rule needs a reviewed schema/contract revision.
- `harness-types` contains contracts and validation only. It does not own policy, persistence, model calls, tools, memory extraction, or orchestration.
- The fixture is an independent static oracle, not a runtime projector or a claim that resume is implemented.
- P0 has no session store, SQLite migration, model/provider, tool execution, memory runtime, multi-agent runtime, Web API/UI, release package, or public compatibility guarantee.

## Consequences

P1 must add kernel/session/SQLite behavior behind these accepted contracts and cannot silently reinterpret a P0 record. P2–P8 remain separate assignments and must not be inferred from the presence of schema types. A caller can inspect or validate P0 data, but cannot use P0 alone to resume a live agent session.

Schema files are regenerated by the checked-in `generate_schemas` binary and compared byte-for-byte with schemas derived from the in-process real types. The generator is a maintenance tool, not a second contract authority.

## Verification boundary

P0 evidence records the exact commands, dependency lock, real component tests, gate self-test, and manual defense mutations. CI is declared for Windows and Linux but has not run until a separately authorized commit/push occurs. The phase must be accepted before assigning P1.
