## 1. Mục tiêu và phạm vi

Thực hiện toàn bộ P0-S01 đến P0-S07 theo [runbook P0](../implementation/P0_FOUNDATION.vi.md): tạo Rust workspace build được, binary `ha` tối thiểu, shared contracts có version, schemas/fixtures continuation, acceptance registry, phase runner fail-closed, CI Rust ban đầu, evidence và restart handoff song ngữ.

P0 chỉ xác nhận contracts và component foundation. Nó không tạo session store, SQLite, model/provider call, LLM loop, tool execution, memory extraction, subagent/worktree orchestration, Web API/UI, release package hoặc durable recovery runtime. C01-C30 và K01-K14 vẫn là `not_implemented` trong registry; P0 không được trình bày chúng là đã pass.

## 2. Inputs và invariants đã chấp nhận

- Binary công khai là `ha`; stdout mang dữ liệu, stderr mang lỗi/log; P0 chỉ hiện thực `--help`, `--version` và `ha config validate --config <path> [--json]`.
- `harness-types` chỉ sở hữu IDs/envelopes/contracts dùng chung; không mang policy, store hay logic agent. `harness-cli` chỉ là presentation/composition tối thiểu.
- Mọi record P0 có `schema_version = 1`; 0 và version chưa hỗ trợ phải bị từ chối. Không đổi nghĩa payload cũ âm thầm.
- ID chuẩn là `<kind>_<uuid-v7-lowercase-hyphenated>`. `kind` là prefix hợp đồng của type; UUID nil, chữ hoa, prefix sai và ký tự thừa đều bị từ chối.
- `seq` durable bắt đầu tại 1; `through_event_seq` không được vượt source sequence được fixture công bố.
- Authority được serialize thành một trong `user`, `host_policy`, `runtime_observed`, `model_proposed`, `external_plugin`; không có authority là lỗi, không suy đoán authority từ payload.
- JSON hash P0 dùng `sha256:<64 lowercase hex>` trên `harness-json-v1`: UTF-8, object keys tăng dần theo byte UTF-8, arrays giữ thứ tự, không whitespace; chỉ `null`, bool, string và integer JSON hợp lệ. Float/exponent bị từ chối để không đóng băng một quy tắc number chưa được xét kỹ. Bổ sung số thực sau này phải là revision contract/schema mới.
- Event envelope giữ producer, authority, correlation/causation optional, `continuity_critical`, object payload và payload hash. `WorkingState`, instruction ledger, immutable tool receipt, memory asset/version, plugin manifest và context packet đều có type/schema riêng.
- Error có code có kiểu, render ổn định `CODE: message`, không in secret hoặc raw config contents. Tối thiểu gồm `invalid_id`, `unsupported_schema_version`, `invalid_sequence`, `missing_authority`, `invalid_payload`, `invalid_hash`, `config_read_error`, `config_parse_error`, `config_unknown_field`, `fixture_integrity`, `gate_configuration_error`, `gate_test_discovery_empty`, `gate_required_test_ignored`.
- Fixture continuation là oracle tĩnh độc lập với projector tương lai: ba yêu cầu đã lưu, hai step hoàn tất, một check fail, một step pending, decision A bị B supersede, user text chưa classify, duplicate input ID, unknown critical event và artifact truncate/corrupt có chủ đích.
- Phase gate phải fail closed: mất registry/fixture, discovery 0 tests, required test ignored, child command nonzero hoặc artifact/evidence thiếu đều là failure. `cargo test` filter rỗng exit 0 không được tính pass.
- Không ghi runtime data, credentials, raw trajectories hoặc evidence vào ignore rộng; `.gitignore` chỉ ignore build output và local runtime paths cụ thể.

## 5. Executable acceptance specification

| ID | Scenario / observable expectation | Real component evidence |
|---|---|---|
| P0-F01 | Given no credentials, `ha --help` and `ha --version` exit 0 and identify only P0-supported command surfaces. | actual compiled `ha` process |
| P0-F02 | Given a valid config fixture, `ha config validate` succeeds; given an unknown field or schema version, it exits nonzero, keeps stdout data-free on error and emits a typed error on stderr. | actual CLI + typed config parser |
| P0-F03 | Every valid P0 record round-trips via JSON and committed schemas exactly match schemas generated by the actual contract types. | `harness-types` serializer/schema generator |
| P0-F04 | Invalid ID, nil/uppercase/prefix-mismatched ID, version 0/2, sequence 0, missing authority, non-object payload and malformed hash are rejected with the matching typed code. | real validators/deserializers |
| P0-F05 | Semantically identical integer JSON objects with reordered keys hash identically; a changed value changes the hash; float/exponent input is rejected. | canonicalizer + SHA-256 |
| P0-F06 | The continuation fixture has contiguous source sequence/hash entries and static expected state with exactly two completed steps, one failed check and one pending step; duplicate input, unknown critical event and corrupt artifacts are visibly represented rather than silently repaired. | fixture loader/integrity verifier, no model/projector |
| P0-F07 | Normal P0 phase gate runs format, clippy, full workspace test, nonempty exact discovery, every required non-ignored P0 test and documentation checks. Its self-test proves known-bad discovery=0, child failure, missing fixture and ignored required test take failure paths. | `scripts/Verify-Phase.ps1` + real Cargo target; simulated Cargo only inside gate self-test boundary |
| P0-F08 | Registry lists P0 foundation cases as required and every C/K future case as `not_implemented`; no future case is passed or silently skipped. CI declares Windows/Linux execution with the pinned toolchain and no credential step. | registry validator + workflow contract test |

The phase acceptance target is `cargo test -p harness-cli --test phase_p0 --locked`; its named tests map one-to-one to P0-F01 through P0-F08. Unit tests remain beside the owner module. A component test never mocks the contract type, CLI, fixture verifier or gate being checked; the only allowed simulation is the Cargo child-process boundary inside the gate's own negative-control harness.

## 6. Failure model and gauntlet

P0 is Tier 3 because future durable/public contract choices can make recovery unsafe if ambiguous. The failure model is: contract drift or unsupported schema accepted; noncanonical hash causes evidence mismatch; unknown config quietly changes behavior; fixture encodes a false recovery oracle; phase checker succeeds while running no test/ignored test; a dependency/toolchain mismatch makes a clone non-reproducible; CI declaration differs from local gate.

Required layers after the final edit:

1. `cargo fmt --all -- --check`.
2. `cargo clippy --workspace --all-targets --locked -- -D warnings`.
3. `cargo test --workspace --all-targets --locked`, then exact P0 target discovery/execution.
4. `pwsh -NoProfile -File scripts/Verify-Phase.ps1 -Phase P0` and `pwsh -NoProfile -File scripts/Verify-Docs.ps1 -SelfTest`.
5. A manual mutation pass against at least five meaningful defences (ID validation, version validation, canonical hash, config rejection, fixture/gate failure); every selected mutant must make a relevant real test/gate fail and then be restored.
6. A real no-credential CLI invocation. CI is declared but cannot be claimed locally run until GitHub executes it; no commit/push is in scope.

No coverage or off-the-shelf mutation tool exists in the initial repository. Installing either is intentionally deferred rather than silently adding global tooling; manual mutations are the P0 replacement and this lower assurance is recorded. Dependency vulnerability scanning is also skipped for lack of an approved local audit tool.

## 8. Verification/restart handoff contract

Evidence must identify base and tested source state, changed files, contract/dependency changes, P0-F mapping, exact commands/results, platform/toolchain, manual mutation results, skipped layers, CI state (`not requested / unverified locally` unless real CI result exists), limitations and next safe action. The two handoffs must list completed P0-S01..S07, file fingerprints, exact restart commands and the only safe successor: request acceptance of P0 before assigning P1.
