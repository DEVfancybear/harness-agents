# Đặc tả triển khai P3 — coding tools và an toàn thực thi

[English](P3.en.md) | Tiếng Việt

Trạng thái: **đặc tả triển khai đang hiệu lực**. SPEC này chỉ cấp quyền cho
P3-S01 đến P3-S07. Không cấp quyền cho P4 memory extraction, P5 multi-agent
scheduling, P6 external plugins, P7 release hardening hoặc P8 Web UI. Trong
autonomous run này không yêu cầu vòng phê duyệt SPEC riêng; assignment P3 của
user là quyền triển khai và file này là contract để review.

## 1. Quyền và bằng chứng predecessor

Assignment trực tiếp P3 yêu cầu P2 đã được nghiệm thu. Trước khi sửa source,
checkout sạch và predecessor đã được xác minh lại:

```text
HEAD / origin/master: 2f9379b1bf2ae64f213606762d66cc448b469610
Commit implementation P2: a34c20ea95f1aeaac67dffc77a7e9cac9ff99234
Digest implementation P2: sha256:947013b3bc1b88def8fabd867b74805072559efd4be4d58ff097cec132bdbf9c
pwsh -NoProfile -File scripts/Verify-Phase.ps1 -Phase P2 -Json: passed
Regression exact P0: 8 pass
Regression exact P1: 18 required pass
Discovery P2: 16 discovered, 15 required, tất cả pass
```

P3 bảo toàn contract P0/P1/P2 đã chấp nhận: schema và ID P0 ổn định, một
SQLite durable writer, fencing ownership task/session, P2 provider request
frozen bất biến, và quy tắc P2 tự nó không thực thi tool.

## 2. Kết quả và ranh giới

P3 thêm `harness-tools`, chủ sở hữu duy nhất của policy coding-tool, approval,
filesystem/search/patch có root, process có cấu trúc, Git inspection, task
update, project identity và immutable execution receipt. Response P2 runtime có
thể đi vào coding-loop adapter P3, nhưng không model/tool call nào bypass cùng
execution gate.

CLI vẫn là lớp composition/presentation. Fixture xác định, không cần key, sẽ
chứng minh response provider P2 thật, parse P3, approval, edit, process verify,
receipt bền vững, recover sau restart và pending-work view mà không cần
credential live. Live provider, sandbox toàn host, network tool, plugin,
browser hay multi-agent scheduler nằm ngoài phase này.

Một action có bốn dạng tách biệt:

1. proposed action — input của model/UI, chưa bao giờ là authority;
2. validated execution intent — action canonical cùng workspace đã resolve,
   fingerprint và quyết định policy, được lưu trước side effect;
3. immutable execution receipt — sự kiện settled/unknown/denied mà observer
   không thể sửa;
4. model/UI view — projection có giới hạn/redact từ immutable record.

Approval bind actor, invocation canonical, argument đã resolve, root/fingerprint
workspace, revision implementation tool và revision policy. Binding đổi, hết
hạn, đã tiêu thụ, cancel, revoke hoặc ancestor deny mạnh hơn đều làm approval
không hợp lệ. Allow xuất hiện sau không thể override parent/ancestor deny.

## 3. Failure model và bất biến bắt buộc

| Failure mode | Phòng vệ và bằng chứng bắt buộc |
|---|---|
| Model hoặc CLI gọi tool ngoài gate | Mọi entrypoint execution public đều gọi một gate `ToolExecutionService::execute`; adapter trực tiếp chỉ expose helper validate, không side effect. |
| Policy transform đổi args sau approval | Validate identity/args, transform, revalidate rồi bind approval vào action/hash canonical cuối. |
| Replay approval, workspace stale, actor mismatch, cancel hoặc revoke | Single-use approval được consume bền vững atomically cùng intent; trước dispatch kiểm tra lại cancel/revoke/fingerprint. |
| Crash sau intent nhưng trước/trong/sau side effect | Commit intent trước dispatch; settle atomically receipt/event/artifact/projection; outcome mơ hồ vẫn `outcome_unknown`, reconciliation inspect chứ không rerun mù. |
| Observer/UI lỗi làm ghi đè history | Receipt immutable và persist trước observer; lỗi observer được record/present riêng. |
| Thoát workspace, traverse symlink/junction, lộ secret, binary/encoding mơ hồ | Canonical rooted path, không traverse symlink/reparse, chặn sensitive path, walk theo `.gitignore` có giới hạn, check UTF-8/binary, hash trước/sau và output redact/bounded. |
| Shell injection, process treo, descendant mồ côi hoặc claim isolation sai | `executable + argv` là mặc định; shell text là action explicit riêng. stdout/stderr bounded, timeout/cancel, Windows Job Object và POSIX process-session cleanup được xác nhận trước settled. Strict isolation bị deny trừ khi capability platform thật tồn tại. |
| Git project identity hay external edit bị lẫn im lặng | Register root canonical và Git common-dir identity; reassociate explicit; fingerprint gồm tracked/untracked state, receipt stale fail khi input đổi. |
| Storage lỗi tạo claim success không được record | Fault injection trước commit tool-intent/settlement chứng minh không có success receipt/projection; reconciliation lộ pending/unknown work. |

## 5. Quyết định data, API và safety

1. P3 dùng revision tools schema additive tên riêng. Không đổi version schema
   P0/P1/P2 hay diễn giải lại record cũ. SQLite writer atomically ghi tool
   intent + consume approval single-use trước dispatch, và atomically ghi
   settlement/receipt/event/artifact scope/projection/sequence marker sau dispatch.
2. `ToolExecutionReceipt` là durable truth. Nó ghi invocation/action hash
   canonical, policy/tool revision, approval ref, fingerprint trước/sau,
   intent/outcome state và event sequence. View cho người/model là derivative
   đã redact/bounded.
3. Workspace root canonical lúc register và mỗi access. Chỉ nhận relative path;
   parent escape, absolute path, symlink/junction, `.harness`, `.git`, credential,
   private key và text operation trên binary/unsupported bị deny bằng stable
   typed error. List/search tôn trọng `.gitignore`, có limit count/byte và không
   follow link.
4. Patch đòi expected content hash exact và source UTF-8. Edit ghi temporary
   sibling, flush rồi replace atomic nơi platform hỗ trợ; mismatch là stale/
   unknown, không overwrite im lặng. Hash trước/sau và diff metadata bounded
   được persist.
5. Process tool nhận `executable + argv`; shell text cần shell action + approval
   explicit. Output được drain khi cap, timeout/cancel kill rồi wait theo tree
   mechanism platform. Windows dùng Job Object; POSIX dùng process session/group.
   Đó là cleanup lifecycle, không phải filesystem/network isolation. `strict`
   isolation là typed denial đến khi sandbox backend thật được cài/verify.
6. Git project identity gồm root canonical + Git common-dir. Identity chuyển/đổi
   đòi reassociation explicit. Git status/diff là read-only. `task_update` chỉ
   đổi task projection, không được giả mạo process runner receipt.
7. Runtime integration một chiều: P2 normalize/trả tool call hoàn chỉnh; P3
   validate/execute/store result. Model args chưa hoàn chỉnh bị deny trước khi
   tool intent được commit. Runtime crate không phụ thuộc ngược P3.

## 6. Setup và dependency được cấp quyền

Giữ nguyên stack Rust 1.97/Tokio/serde/sqlx. Phase này có thể thêm các workspace
dependency pin chính xác sau, được ghi trong `Cargo.lock`:

- `ignore = 0.4.25` (`Unlicense OR MIT`): walker tương thích `.gitignore` đã
  được dùng rộng rãi cho list/search rooted, bounded. Metadata 0.4.25 đã được
  inspect local; nó không kích hoạt process/external service.
- `process-wrap = 10.0.0` (`Apache-2.0 OR MIT`, MSRV 1.87): safe Tokio wrapper
  cho Windows Job Object và POSIX process-session/process-group cleanup mà
  không thêm unsafe code vào workspace. Source/feature surface đã inspect local.
  Chỉ bật `tokio1`, `job-object`, `process-session`, `kill-on-drop`.
- `tokio = 1.53.1` đang pin được thêm feature `process` để chạy subprocess test
  và execution thật.

Không cài/kích hoạt credential, privileged host service, external database,
live model call hay deployment. Acceptance target là
`crates/harness-cli/tests/phase_p3.rs`; P3 sở hữu crate `harness-tools` mới,
wiring additive types/store/session/runtime/provider, CLI composition,
phase registry/gate và evidence/handoff song ngữ.

## 7. Gate và nghĩa vụ evidence

P3 gate phải chạy format, clippy, workspace test, exact regression P0/P1/P2,
P3 discovery không rỗng/ignored và docs self-test. Behavior bắt buộc dùng
SQLite, file, Git và subprocess local thật; chỉ boundary external/provider mới
được dùng fixture local xác định. Evidence cuối phải ghi một gate sau code edit
cuối, source digest chỉ loại metadata P3 evidence/handoff, platform/tool version,
lỗi/sửa lỗi, capability platform và mọi layer skip (coverage/mutation, live
provider, platform chưa chạy nếu có).

Deliverable bắt buộc là `docs/evidence/P3.en.md`, `P3.vi.md`,
`docs/handoffs/P3.en.md` và `P3.vi.md`. Dừng sau P3, không cấp quyền P4 hay
runtime deployment.
