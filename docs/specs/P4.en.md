## 2. Selected scope and architecture

- Add `harness-memory` as owner of memory contracts, publication policy,
  extraction/retrieval/invalidation services, and deterministic external-boundary
  mocks.
- Add a separate memory schema revision to `harness-store-sqlite`. Every asset,
  version, grant, binding, dependency, job, and cursor write uses the existing
  coordinator and host fence; no second database authority is introduced.
- Runtime/context composition receives only proposed optional blocks and exact
  memory version references. The P2 `ContextBuilder` remains the sole admission,
  budget, ordering, and context-freeze component.
- Add CLI `memory search/read/inspect/invalidate/jobs/catch-up`. The host constructs
  a validated principal/scope; model payloads never confer authority.
- Extend the registry, phase verifier, and CI matrix from P0-P3 through P4, then
  stop before P5.

SQLite FTS5/BM25 is the baseline. A vector adapter is only an optional boundary
used to prove degradation; production vector support is not claimed. L3 becomes
active only through confirmed user/manual publication. Physical purge,
Tencent/Redis/vector databases, daemon mode, real embeddings, and network calls
are out of scope.

## 3. Data and policy contracts

1. Host-issued `MemoryPrincipal` carries principal plus project/task/profile/
   session scopes. Search, direct read, inspect/export, publish, bind, and
   invalidate all enforce action and object scope. Identities inside model or
   extractor payloads have no authority.
2. Assets have immutable versions and a CAS current pointer. Status
   `candidate|active|superseded|invalidated|archived` is separate from validity
   `valid|stale|unknown`. Confidence is a ranking annotation, not authority.
3. Publication permits validated runtime observations to become active by policy;
   model inferences remain candidates; a user decision may supersede an older
   version; profile L3 requires `SourceAuthority::User` and explicit publication.
4. Immutable source batches contain a stream, inclusive sequence range, ordered
   source IDs and payload hashes, extractor version, and strategy digest. Jobs move
   `pending -> leased -> completed|retry_wait|blocked|paused|dead_letter`; stale
   lease generations cannot settle.
5. Cursor key is `(source_stream, extractor_version, strategy_digest)` and denotes
   only a contiguous prefix with recorded dispositions. `no_facts` advances it;
   unavailable, invalid output, and extraction failure do not. A new strategy has
   an explicitly selected replay start.
6. Dependencies retain transitive event/file/asset-version lineage. Injected
   context, extractor output, and derived summaries cannot become independent
   evidence.
7. Retrieval returns `found|empty|degraded|error`, scopes before top-k, uses
   parameterized queries, normalizes Unicode/accentless Vietnamese/snake/camel
   identifiers, and bounds hits/tokens/time. Revisions are rechecked before dispatch.
8. Memory calls/source bytes/output bytes have a separate finite budget. Budget
   exhaustion or shutdown durably pauses work; catch-up resumes only under a new
   finite budget.

## 4. Tier 3 failure model

| Failure mode | Defense and test |
|---|---|
| Forged actor/project or hash lookup crosses scope | Host principal plus grant/scope query before LIMIT; C08 direct-read/export negatives. |
| Lost update or last-write-wins | Transactional expected-version CAS; three concurrent proposals in C07. |
| Crash between asset/job/cursor writes | One settlement transaction and pre-commit fault injection; C12. |
| Overlap, timestamp collision, or out-of-order settlement | Ordered immutable sequence ranges and contiguous cursor; C16/C17. |
| Stale worker or forged extractor source references | Lease-generation and output validation; C12/C22. |
| Self-reinforcing memory or obsolete decisions | Transitive provenance, supersession, and invalidation; C09/C13/C20. |
| Optional service failure loses current task | Journal/WorkingState-only resume and typed degradation; C05/K02. |
| FTS injection or poor Vietnamese/code recall | Parameterized MATCH terms, normalized mirror, exact identifier fallback; C26. |
| Mandatory rules compete with top-k | Separate mandatory P2-builder path; C18/C19 strengthening. |
| Cached/request revision is revoked | Snapshot validation immediately before dispatch; C20/K10. |
| Unbounded background spend or abandoned CLI claim | Finite budgets, bounded retries, durable pause; C30. |
| Secret/artifact leakage | No credential capture, scoped content, and strengthened P3 C29 regression. |

## 6. Test loop and gauntlet

The acceptance target uses real `SqliteStore`, session/runtime/context builder,
FTS5, and CLI binary over temporary data directories. Only extractor,
vector/embedding, and suitable clock/cancellation boundaries are mocked. The
transaction engine, authorization, FTS, context builder, and component under test
are never mocked.

The first RED run must discover the P4 target and fail because required API or
behavior is absent. Implement S01-S07 in dependency order and run the related
target after each slice. Final gate:

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --all-targets --locked
cargo test -p harness-cli --test phase_p4 --locked
pwsh -NoProfile -File scripts/Verify-Phase.ps1 -Phase P4 -Json
pwsh -NoProfile -File scripts/Verify-Docs.ps1 -SelfTest
```

Verify non-empty/non-ignored discovery and exact P0-P3 regressions. Run property
tests for CAS/cursor/normalization where appropriate, 3-5 manual mutants when no
mutation tool exists, gate negative controls, and adversarial forged scopes/ranges.
Coverage, mutation, audit, or platform gaps must be recorded honestly.

## 9. Implementation addendum

No external package versions changed. Existing workspace dependencies are reused:
`harness-session` for context contribution, `tokio-util` cancellation, `proptest`
for normalization properties and `sqlx` in acceptance tests for read-only row-count
assertions. Tokio's existing `signal` feature enables graceful CLI cancellation.
Runtime gains an optional memory contribution and validates revision before every
provider attempt; P2 freezes only version refs for blocks it actually admitted.

Manual publication and source-versioned L2 merge/summary commands complete the
controlled profile/semantic-merge interface. Bootstrap/index bindings contribute
at most eight records within 2,000 estimated tokens. Source changes invalidate
transitive derived assets; historic versions remain available under current grants.

Additional acceptance fixtures cover transitive grant revocation, provider retry
revocation, source changes/merges/bindings and cancellation during extraction.
`Verify-P4Gauntlet.ps1` runs five receipt-proven manual mutants in a disposable
source copy, restored tests/properties, then the final phase gate. Coverage,
advisory scanning and independent agents remain explicitly reported layers, not
implied by the phase gate.

## 10. Final integrity regressions

The source/binding fixture also requires the host-issued binding ID to round-trip
unchanged; a binding ID cannot be reassigned to another asset/principal. The S05
fixture mutates rendered text and requires `InvalidHash` before snapshot validation.
A private rendering seal detects post-contribution edits; it is an integrity check,
not isolation from arbitrary hostile code inside the trusted host process.
