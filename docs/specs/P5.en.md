## 2. Scope and chosen architecture

- Create `crates/harness-orchestrator/` as the owner of delegation contracts,
  the task DAG, worker scheduling, worktree isolation, result integration and
  delegated crash recovery. This is the logical owner `harness-orchestrator`
  already named in the implementation handbook; it is not a second agent engine.
- Extend `harness-store-sqlite` with additive delegation tables under their own
  schema revision. Every task, ownership, result, delivery and workspace write
  goes through the existing transaction coordinator and host fence.
- Reuse the P2 runtime as the worker engine: workers are presets of
  `RuntimeService` created by a host-owned factory with their own session, inbox,
  cancellation token and context. No second runtime is introduced.
- Extend `harness-tools` with the host-owned Git worktree operations the
  orchestrator needs, so shared Git metadata stays in one implementation.
- Extend the CLI with `ha run --agents N`, task status/result/cancel/handoff
  views and a deterministic multi-agent demo fixture.
- Extend the acceptance registry, the phase verifier and the CI matrix from
  P0–P4 to P5. Stop before P6.

Worker execution stays inside the one writable host process. A daemon, remote
workers, a marketplace, background execution after CLI exit, and true sandbox
isolation between in-process workers are out of scope. Worktrees isolate
concurrent edits; they are not a security boundary, and no artifact may claim
otherwise.

## 3. Contracts to fix before implementation

1. `TaskBrief` is host-authored and versioned: objective, acceptance criteria,
   inputs, base snapshot, grants, budget, deadline, expected artifacts and the
   role preset reference. A role name grants nothing; every authority field is
   an explicit host value.
2. `AgentRole` is a preset of the same runtime. `AgentProfileId` is stable across
   activations, `AgentRunId` is one activation, and the ownership generation
   fences a dead run.
3. Task lifecycle is `pending -> ready -> assigned -> running -> completed |
   failed | canceled`, with `blocked` reachable from any live state. Dependencies
   form a DAG: cycles, self-dependencies, unknown dependency IDs, duplicate task
   IDs and ambiguous owners are rejected before admission.
4. A worker report is not host-accepted completion. `DelegatedResult` carries
   outcome, summary, artifact references, base and result revisions, the checked
   revisions and check receipts. Empty responses, or a human-readable "done"
   without the declared artifacts and receipts, must not settle accepted work.
5. Results are produced against a revision: per-worker branch revisions are not
   integrated-revision evidence, and integration re-runs final checks.
6. Budget covers concurrent workers, delegation depth, model requests and
   computed cost. Missing usage is not zero, and exhausted budget is terminal
   for new dispatch rather than silently unbounded.
7. Delivery is exactly-once *logically*: the child result, its task transition
   and the parent delivery commit in one transaction; a notification only wakes a
   reader. Consumption is idempotent by stable message ID, and a pending parent
   session receives inbox data without an arbitrary append to its event log.
8. Editing delegation requires a verified clean repository input. Dirty input is
   refused with an explicit reason until a preservation-tested snapshot path
   exists; user changes are never stashed, reset or discarded.
9. Parent cancel and parent pause are different operations: cancel cascades to
   descendants, pause preserves durable state for resume.

## 4. Failure model

| Failure mode | Defense |
|---|---|
| Circular or ambiguous delegation | DAG validation before admission; cycle/dangling/self/duplicate tests. |
| Completed work re-dispatched after restart | Durable task state is authority; recovery never reassigns `completed` tasks or a dead run's finished child. |
| Lost parent notification | Result plus delivery plus task transition in one transaction; replay delivers once logically with the original result reference. |
| Duplicate delivery consumption | Stable message ID with a consumed flag checked inside the write transaction. |
| Parent waits and starves its children | Waiting releases the compute permit; fairness test with slots below the child count. |
| Worker edits overlap or escape scope | Host-owned worktrees from one verified snapshot, per-worker branch, declared write scope, blocked out-of-scope change. |
| Concurrent shared Git metadata corruption | One serialized Git metadata lock plus an integration worktree; concurrent worktree creation test. |
| Dirty input silently destroyed | Clean-input requirement, explicit refusal, no stash/reset, preservation assertions. |
| Branch receipt promoted to integrated evidence | Integration re-checks fingerprints and re-runs final checks on the integrated revision. |
| Child result forges scope or exceeds grants | Host-created principals; delegated memory access re-checks the child's scope before dispatch. |
| Uncertain child side effect marked completed | `outcome_unknown` reconciliation at the coordinator; unknown never becomes accepted. |
| Budget or depth exceeded | Typed `budget_exhausted`/`depth_exceeded` refusal; depth-cap and budget tests. |
| Shutdown loses descendants | Cancel/drain descendants, one shared shutdown completion, store closed last. |
| Semantic memory used as task authority | Completion comes only from durable task state. |

## 6. Tests, RED/GREEN and gate

The acceptance target is `crates/harness-cli/tests/phase_p5.rs` with additional
modules next to it. Tests use the real `SqliteStore`, real session/runtime
services, the real policy gate and tool service, real `git` repositories created
in temporary directories, and the compiled `ha` binary. Only genuinely external
boundaries are mocked: the model provider, the extractor/embedding boundary and
the clock. The transaction engine, authorization, the DAG store, worktree
management and the scheduler are never mocked.

RED first, then GREEN per slice. Final gate:

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --all-targets --locked
cargo test -p harness-cli --test phase_p5 --locked
pwsh -NoProfile -File scripts/Verify-Phase.ps1 -Phase P5 -Json
pwsh -NoProfile -File scripts/Verify-Docs.ps1 -SelfTest
```

Discovery must be non-empty and must not ignore required cases; predecessor
regressions P0–P4 run as exact named tests. Layers that cannot be run in this
environment (mutation tooling, coverage, advisory audit, multi-OS CI) must be
reported as skipped or open, never inferred from a local pass. The Windows
`git clone` restriction noted in section 1 means the full workspace suite needs
unrestricted process/pipe access; if a run lacks it, the failure must be reported
as an environment limitation with the reproduction, not as a P5 defect.
