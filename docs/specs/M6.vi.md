## 5. Contracts

### 5.1 Port contributor (M5 sở hữu, M6 là consumer đầu tiên)

`CONTRIBUTORS` trong CONTRACTS §7 là `contributor.collect(readonly_scope, token_limit) -> ProposedBlock[]`. M5 chưa dựng port (đã kiểm: chỉ có comment ở `context.rs:169`). M6 dựng port tại `crates/harness-session/src/context.rs`:

```rust
pub struct ContributorScope<'a> {
    pub session_id: SessionId,
    pub task_id: TaskId,
    pub source_revision: u64,
    pub config_revision: u64,
    pub workspace_root: Option<&'a Path>,
}

pub trait ContextContributor: Send + Sync {
    fn contributor_id(&self) -> &str;
    fn collect(&self, scope: &ContributorScope<'_>, token_limit: u64)
        -> Result<Vec<ContextBlock>, ContextError>;
}
```

**Invariant.** Contributor không thể nâng quyền: block trả về đi qua **đúng** đường `optional_blocks` của compiler, nên `block.mandatory = block.mandatory && block.channel.may_be_mandatory()` áp dụng y nguyên, và block vào `channel_digest` của manifest. Không có đường nào để contributor ghi thẳng vào packet.

**Quyết định đóng hộp (khác default):** `ContextBuilder::build(request)` giữ nguyên chữ ký; thêm `ContextBuilder::build_with_contributors(request, &[Arc<dyn ContextContributor>])`. Lý do: `ContextBuildRequest` là struct literal ở 8 call site (milestone_m5 ×2, phase_p2 ×4, phase_p4 ×1, runtime ×1); thêm field sẽ sửa 4 file test của M4/M5 mà không thêm giá trị. Test chứng minh tương đương: `build(r)` ≡ `build_with_contributors(r, &[])`.

### 5.2 Skill channel

Thêm `ContextChannel::Skill` + `ContextBlockKind::Skill`:
- `may_be_mandatory() == true` — một skill đã được user **activate tường minh** là chỉ dẫn authored, cùng lớp với project rule.
- `default_authority() == SourceAuthority::User`.
- `label()` → `"activated skill <name>@<version>"`.

**Ranh giới quyền:** channel này nói block **được gửi**; nó không nói skill được **làm** gì. `requested_tools`/`requested_secrets` vẫn phải qua `SkillDescriptor::authorize` và qua gate M4 (`ToolService::prepare/execute`). Không có nhánh nào biến text của skill thành grant.

### 5.3 Catalog (M6-04)

```text
ToolCatalog { revision, catalog_digest, entries: [CatalogEntry] }
CatalogEntry { id, source: CatalogSource, revision, schema_digest, effect_class,
               capabilities, summary, schema: Option<Value> }   // schema = None ⇒ deferred
list_authorized(capabilities) -> [CatalogNameView]              // tên + metadata, KHÔNG schema
promote(id, expected_catalog_digest, policy_revision, capabilities)
    -> PromotedTool | SchemaVersionMismatch | PolicyDenied | FrameLimitExceeded
PromotedTool { catalog_digest, id, schema_digest, schema, policy_revision, catalog_revision }
    .revalidate(current: &ToolCatalog, policy_revision) -> Result<(), ExtensionError>
ToolCatalog::invalidate(id) / rebuild(...)   // reload/revoke ⇒ promoted cũ stale
```

**Bất biến.** Discovery permission ≠ invocation permission. `promote` chỉ trả schema; quyền gọi vẫn do gate M4 quyết ở mỗi proposal. `revalidate` chạy **ngay trước** dispatch; `policy_revision` hoặc `schema_digest` đổi ⇒ typed reject, không dùng schema cũ.

### 5.4 Protocol frame bổ sung (M6-02)

`FrameKind::Cancel` + `ExtensionFrame::cancel(id)`. `ExtensionTransport::cancel_call(id, grace_ms)`:
1. gửi frame `cancel` cho `id`;
2. chờ tối đa `CANCEL_GRACE_MS` (2000) cho outcome đang pending;
3. plugin trả error code `canceled`/`cancelled` ⇒ `CallOutcome::Canceled`;
4. hết grace ⇒ `terminate_process_tree()` + `CallOutcome::Uncertain` (bounded, **không** treo vô hạn).

Transport thêm trạng thái `dead: AtomicBool`; `terminate_process_tree` set nó; mọi `call*` sau đó trả `Err(ServiceUnavailable)` thay vì ghi vào stdin đã đóng.

## 6. ADR (đến hạn theo runbook §1)

- **ADR-N06a — traits/process protocol/MCP separation.** Ba tầng tách biệt: (1) `ContextContributor` là trait đồng bộ, chỉ đọc, không I/O mạng; (2) protocol extension là NDJSON có version trên stdio, host là bên duy nhất cấp id; (3) MCP là **SDK ngoài** (`rmcp`), không bao giờ được trộn với protocol nội bộ — `McpClient` không implement `ExtensionTransport` và không đi qua handshake nội bộ. Hệ quả: một lỗi ở tầng MCP không thể làm sai lệch ngữ nghĩa frame nội bộ, và ngược lại.
- **ADR-N06b — scope lifecycle.** Một extension sống trong đúng một `ScopeId`, có `generation` tăng đơn điệu. Handle cấp cho consumer là `ExtensionLease` gắn generation; lease cũ **không** dispatch được sau reload/unload (`ServiceUnavailable`). Registration gỡ bằng token chính xác nên disposer muộn không xoá được thế hệ mới (đã có ở P1, M6 chỉ thêm consumer).
- **ADR-N06c — compatibility matrix.** Nguồn duy nhất cho "cái gì chạy được" là `McpSupportMatrix` (MCP) + `supported_protocol_versions()`/`supported_host_methods()` (protocol nội bộ) + `InactiveReason` (vì sao không chạy). `ha extensions capabilities` và `ha extensions config-explain` đọc từ các nguồn này; không có danh sách viết tay thứ hai.
- **ADR-N06d — cancel là best-effort có biên.** Host không thể cưỡng chế một process bên ngoài dừng đúng lúc; hợp đồng chỉ hứa: cancel được **gửi**, và nếu không được tôn trọng trong `CANCEL_GRACE_MS` thì process tree bị kết thúc và outcome là `Uncertain` (không bao giờ là success). Đây là giới hạn thật, ghi ở evidence.

## 10. Quyết định khác bản nháp (ghi rõ, không đổi ngầm)

1. **`EXTENSION_PROTOCOL_VERSION` giữ 1** dù thêm `FrameKind::Cancel`. Bản nháp ban đầu định bump lên 2; bump sẽ từ chối mọi plugin P6 hợp lệ mà không có lợi ích. Bù lại: `ExtensionFrame::decode_line` đã từ chối `protocol_version` khác 1, nên plugin cũ gửi frame cancel sẽ bị từ chối typed — đúng hướng fail-closed.
2. **`build_with_contributors` thay vì thêm field vào `ContextBuildRequest`** (§5.1).
3. **Skill channel được phép mandatory** (§5.2). Đây là quyết định có rủi ro review: nếu reviewer cho rằng skill phải luôn optional, đổi `may_be_mandatory` cho `Skill` là thay đổi một dòng + một assert.
4. **`McpToolDispatcher` là đường duy nhất tới MCP server.** P6 gọi qua dispatcher; `McpClient::call_tool` là `pub(crate)`. Compile-fail N8-MCP chứng minh crate ngoài không thể gọi transport trực tiếp.
5. **`harness-extensions -> harness-session` edge mới** (§5.6).
6. **`ha extensions skills` đổi payload JSON.** Lệnh này chuyển từ `discover_skills`+`compose_skills` sang `SkillCatalog`, nên payload thêm `catalog_digest`, `conflicts` (có `conflict_id`), `byte_len`, `content_loaded`; bỏ `replaced`. **Giữ nguyên** `skill_count` và `grants_resolved` — đây là hai field mà regression `p6_s07` khẳng định, và cả hai vẫn đúng nghĩa (2 skill trong fixture, 0 grant được resolve). Không đổi `schema_version`, không đổi exit code, không đổi tên subcommand. Lý do đổi: một listing đọc metadata thì phải nói rõ nó **chưa** đọc content (`content_loaded: false`) và phải nói được xung đột giữa các nguồn bằng một id ổn định; `replaced` cũ không có id nên không đối chiếu được giữa hai lần chạy.

## 11. Platform, mock, giới hạn

- **Mock:** chỉ mock provider/network ngoài (không dùng). Store/runner/transport/gate đều là component thật.
- **Thật:** mọi fixture là binary thật của repo, chạy qua `std::process`, giao tiếp bằng protocol thật.
- **OS:** `process_wrap` dùng `JobObject` (Windows) / `ProcessSession` (Unix) qua `cfg!`-style cặp `#[cfg]` sẵn có. Nhánh Unix **không** chạy được trên host này (không WSL/Docker — handoff M5 §9). A22/A23/A24 chỉ được chứng minh trên Windows trong lượt này ⇒ ghi `platform pending` cho Linux.
- **MCP:** stdio và Streamable HTTP + bearer từ env được nối vào chat; mọi entry `McpSupportMatrix` được advertise và kiểm thử. SSE/OAuth, sampling kèm tools/ảnh, multi-round input, tự mở rộng RFC 6570 resource template URI và chạy MCP task như Complete tool result không được hỗ trợ. Marketplace, WASM và dynamic ABI cũng ngoài phạm vi.
