# Đặc tả triển khai P2 — runtime, context và compaction

[English](P2.en.md) | Tiếng Việt

Trạng thái: **đặc tả triển khai đang hiệu lực**. SPEC này chỉ cấp quyền cho
P2-S01 đến P2-S07. Không cấp quyền cho coding tools/process P3, memory

Trong autonomous run này chưa có vòng user phê duyệt SPEC riêng; assignment
của user là quyền triển khai và file này là contract để review.

sạch và source P1 đã chấp nhận được xác minh:

Evidence và restart handoff P1 đã publish là nguồn chuẩn cho contract

writer SQLite, fencing task/session và semantics recovery P1 không đổi.

## 2. Kết quả và ranh giới

P2 thêm single-agent runtime có thể chạy model loop xác định, không cần key
thật, qua provider interface; dựng context packet giải thích được; đóng băng
và lưu request trước dispatch; compact nhiều lần mà không xóa history gốc; và
resume/replay sau restart process/session.

Runtime là application service; CLI chỉ compose và trình bày. Provider chuẩn
hóa message, tool-call delta, stream terminal event, capability, cancellation
và retry có giới hạn. DeepSeek adapter dùng HTTP/SSE tương thích OpenAI, nhận
credential do host resolve và tuyệt đối không lưu credential trong request,
packet, event, log hay snapshot. Test dùng HTTP fixture local hoặc provider
trong bộ nhớ; không cần credential live hay API trả phí.

Mandatory context được lắp ngoài optional retrieval: system policy, instruction
user/project hiện hành (kể cả text `unclassified`), objective, acceptance
criteria, decision và supersession hiện tại, WorkingState, cặp tool chưa settle
và recent tail liên quan. Optional contributor chỉ được tính sau mandatory.
Nếu mandatory không vừa sau output reservation, protocol overhead và safety
margin, runtime pause với lý do có kiểu thay vì bỏ yêu cầu.

Compaction ghi marker bắt đầu, dựng candidate ngoài SQL transaction, kiểm tra
coverage mandatory và commit checkpoint bằng CAS. Tail đổi thì retry/rebase;
summary/provider lỗi dùng fallback xác định từ WorkingState + event tail. Raw
event vẫn bền vững. Context packet và composition snapshot chứa exact rendered
content, source ref có thứ tự, version, config hiệu lực không secret và hash.

Resume phục hồi state/ownership mà không tự chạy lại side effect chưa rõ. Session
mới chỉ tiếp tục task sau khi lease cũ stale và takeover an toàn. Offline replay
chỉ đọc frozen packet/diagnostic: không dispatch model, network hoặc tool.
Unknown critical event hoặc projector/composition version không hỗ trợ chặn
execution resume nhưng vẫn cho inspect read-only packet/history.

## 3. Failure model và bất biến bắt buộc

| Failure mode | Phòng vệ và bằng chứng |
|---|---|
| Actor/turn transition sai hoặc command trùng | State machine có kiểu từ chối transition; command ID bền vững idempotent, claim có attempt giới hạn. |
| Provider chunk tách, JSON sai, tool args dở, transport lỗi hoặc cancel | SSE decoder tăng dần trả normalized event/error; tool call chưa hoàn tất không executable; cancel được quan sát, retry có giới hạn. |
| Lộ credential | Resolver chỉ đưa secret vào outbound adapter; request/packet/attempt JSON lưu đã sanitize và test scan. |
| Bỏ mandatory context hoặc vượt budget | Admission mandatory có thứ tự, độc lập ranking optional; overflow trả pause reason và không dispatch provider. |
| Config/context đổi khi request chạy | Composition/request là record immutable; revision sau chỉ áp dụng ở step boundary mới. |
| Summary lỗi, CAS compaction stale hoặc compact lặp | Fallback xác định, xử lý CAS conflict, giữ raw journal và property năm lần compaction. |
| Crash/reopen, task lease stale hoặc critical event lạ | Recovery receipt bền vững, takeover generation an toàn, block execution + offline inspect, không replay mù. |
| CLI vô tình thành runtime authority | Test gọi application service trực tiếp; CLI chỉ presentation, mutation đi qua runtime/store boundary. |

## 5. Quyết định data và API

1. Giữ event và WorkingState P0/P1 ở version 1. Bảng runtime additive có
   revision schema riêng; không diễn giải lại row cũ.
2. `ModelProvider`, `CredentialResolver`, context builder và runtime service
   dùng boxed future object-safe hoặc validate đồng bộ + async call boxed. Không
   có Rust ABI hay native dynamic plugin boundary.
3. Provider request có role/message/tool schema normalized và capability snapshot.
   Provider-private field chỉ giữ trong namespace adapter explicit và loại khỏi
   persistence sanitize nếu chưa có test chứng minh không có credential.
4. Hash `ContextPacket` bao phủ exact rendered UTF-8. Source manifest và
   memory-version list immutable, có thứ tự. Frozen request tham chiếu hash
   packet/composition và lưu body sanitized thực sự đã dispatch.
5. Runtime event chỉ continuity-critical khi phase này có decoder. Unknown
   critical chặn active resume; offline inspect trả packet/history diagnostic.
6. Takeover task chỉ được phép khi lease generation trước stale sau khi writer
   cũ release ownership. Hai session trong cùng host generation vẫn conflict.

## 6. Setup và dependency được cấp quyền

Implementation dùng stack Rust 1.97/Tokio/serde/sqlx hiện có, cộng các
workspace dependency pin:

- `tokio-util = 0.7.16`: cancellation token truyền qua runtime/provider.
- `reqwest = 0.12.24` với `json`, `stream`, `rustls-tls`: DeepSeek HTTP/SSE
  adapter HTTPS; test chỉ trỏ local fixture.
- `futures-util = 0.3.34`: đọc bounded response byte stream của adapter; pin này
  tương thích với dependency range của `sqlx 0.9.0`.

Không cài/kích hoạt credential, external service, database hay tool. `Cargo.lock`
ghi exact transitive set. Acceptance target là
`crates/harness-cli/tests/phase_p2.rs`; P2 source thuộc `harness-runtime`,
`harness-providers`, module additive session/store và CLI composition.

## 7. Gate và nghĩa vụ evidence

P2 gate phải chạy format, clippy, workspace tests, regression exact P0/P1,
discovery P2 không rỗng/ignored và docs self-test. Evidence cuối ghi một run
mới sau code edit cuối, source digest loại đúng metadata evidence/handoff P2,
các layer skip (live provider smoke, coverage/mutation nếu tool không có, Linux
nếu chưa chạy), lỗi và cách sửa, platform/tool versions.

Deliverable bắt buộc là `docs/evidence/P2.en.md`, `P2.vi.md`,
`docs/handoffs/P2.en.md` và `P2.vi.md`. Dừng sau P2, không cấp quyền P3 hay
deploy runtime.
