## 1. Objective and scope

Deliver P0-S01 through P0-S07 from the [P0 runbook](../implementation/P0_FOUNDATION.en.md): a buildable Rust workspace, minimal `ha` binary, versioned shared contracts, continuation schemas/fixtures, acceptance registry, fail-closed phase runner, initial Rust CI, and bilingual evidence plus restart handoff.

P0 validates only contracts and foundation components. It does not create a session store, SQLite, model/provider call, LLM loop, tool execution, memory extraction, subagent/worktree orchestration, Web API/UI, release package, or durable recovery runtime. C01-C30 and K01-K14 remain `not_implemented` in the registry; P0 must not present them as passing.

## 2. Accepted inputs and invariants

- The public binary is `ha`; stdout carries data and stderr carries errors/logs. P0 implements only `--help`, `--version`, and `ha config validate --config <path> [--json]`.
- `harness-types` owns only shared IDs/envelopes/contracts; it carries no policy, store, or agent logic. `harness-cli` is only minimal presentation/composition.
- Every P0 record has `schema_version = 1`; 0 and unknown versions are rejected. Old payload meaning is never silently changed.
- The canonical ID is `<kind>_<uuid-v7-lowercase-hyphenated>`. `kind` is the type's contract prefix; nil UUIDs, uppercase, wrong prefixes, and extra characters are rejected.
- Durable `seq` begins at 1; `through_event_seq` cannot exceed the source sequence declared by a fixture.
- Authority serializes to exactly one of `user`, `host_policy`, `runtime_observed`, `model_proposed`, `external_plugin`; a missing authority is an error and never inferred from payload.
- P0 JSON hashing uses `sha256:<64 lowercase hex>` over `harness-json-v1`: UTF-8, object keys ascending by UTF-8 byte order, arrays preserved, no whitespace, and only JSON `null`, bool, string, and integers. Float/exponent input is rejected rather than freezing an unreviewed number rule. Adding real numbers later requires a new contract/schema revision.
- The event envelope retains producer, authority, optional correlation/causation, `continuity_critical`, object payload, and payload hash. WorkingState, instruction ledger, immutable tool receipt, memory asset/version, plugin manifest, and context packet each have their own type/schema.
- Errors have typed codes and stable `CODE: message` rendering and must never print secrets or raw config contents. The minimum set is `invalid_id`, `unsupported_schema_version`, `invalid_sequence`, `missing_authority`, `invalid_payload`, `invalid_hash`, `config_read_error`, `config_parse_error`, `config_unknown_field`, `fixture_integrity`, `gate_configuration_error`, `gate_test_discovery_empty`, and `gate_required_test_ignored`.
- The continuation fixture is a static oracle independent of a future projector: three persisted requirements, two completed steps, one failed check, one pending step, decision A superseded by B, unclassified user text, duplicate input ID, unknown critical event, and intentionally truncated/corrupt artifacts.
- The phase gate fails closed: a missing registry/fixture, zero-test discovery, an ignored required test, a nonzero child command, or missing artifact/evidence is failure. A filtered `cargo test` that exits zero after executing no test is not a pass.
- Runtime data, credentials, raw trajectories, and evidence are not broadly ignored; `.gitignore` only ignores build output and named local-runtime paths.

The toolchain pin is Rust `1.97.1`, `minimal` profile, with `rustfmt` and `clippy`; the local inventory before implementation is rustc/cargo 1.97.1 on `x86_64-pc-windows-msvc` and PowerShell 7.6.5. CI installs this pin; the local run installs no new global tool.

|---|---|---|
| `serde = 1.0.229` + derive | MIT OR Apache-2.0 | typed, strict serialization |
| `serde_json = 1.0.151` | MIT OR Apache-2.0 | JSON contracts, fixtures, canonical input |
| `schemars = 1.2.2` | MIT | reproducible JSON Schema from real types |
| `thiserror = 2.0.20` | MIT OR Apache-2.0 | typed error rendering |
| `sha2 = 0.11.0` | MIT OR Apache-2.0 | SHA-256 contract hash |
| `uuid = 1.26.1` + `serde`,`v7` | Apache-2.0 OR MIT | stable typed IDs |

Crate versions/licenses/MSRV were read from crates.io before resolution; all declared MSRVs are at or below Rust 1.97.1. `toml` was added in this SPEC revision after establishing that typed config parsing must not be a hand-written parser; Cargo.lock retains package metadata `+spec-1.1.0`, while the requirement must be `=1.1.5` because Cargo ignores SemVer build metadata. Cargo may download these exact public packages into its ordinary local cache and write the repository `Cargo.lock`. No `cargo install`, global package installation, API key, provider request, secret, database, or public publish is authorized. P0 does not install a full vulnerability/license audit tool; evidence records direct-dependency license evidence and the locked tree, plus that limitation.

## 5. Executable acceptance specification

| ID | Scenario / observable expectation | Real component evidence |
|---|---|---|
| P0-F01 | With no credentials, `ha --help` and `ha --version` exit 0 and identify only P0-supported command surfaces. | compiled `ha` process |
| P0-F02 | A valid config fixture succeeds through `ha config validate`; an unknown field or schema version exits nonzero, leaves stdout data-free on error, and emits a typed stderr error. | CLI + typed config parser |
| P0-F03 | Every valid P0 record round-trips through JSON and committed schemas exactly match schemas generated by real contract types. | `harness-types` serializer/schema generator |
| P0-F04 | Invalid ID, nil/uppercase/wrong-prefix ID, version 0/2, sequence 0, absent authority, non-object payload, and malformed hash are rejected with the matching typed code. | validators/deserializers |
| P0-F05 | Equivalent integer JSON objects with reordered keys hash identically; a changed value changes the hash; float/exponent input is rejected. | canonicalizer + SHA-256 |
| P0-F06 | The continuation fixture has contiguous source sequence/hash entries and a static expected state with exactly two completed steps, one failed check, and one pending step; duplicate input, unknown critical event, and corrupt artifacts are represented rather than silently repaired. | fixture loader/integrity verifier, no model/projector |
| P0-F07 | The normal P0 gate runs format, clippy, full workspace tests, nonempty exact discovery, every required non-ignored P0 test, and documentation checks. Its self-test proves that discovery=0, a child failure, a missing fixture, and an ignored required test take failure paths. | `scripts/Verify-Phase.ps1` + real Cargo target; simulated Cargo only inside the gate's self-test boundary |
| P0-F08 | The registry lists P0 foundation cases as required and every future C/K case as `not_implemented`; no future case is passed or silently skipped. CI declares pinned-toolchain Windows/Linux execution with no credential step. | registry validator + workflow contract test |

The phase acceptance target is `cargo test -p harness-cli --test phase_p0 --locked`; named tests map one-to-one to P0-F01 through P0-F08. Unit tests live beside their owning modules. A component test never mocks the contract type, CLI, fixture verifier, or gate being checked; the sole permitted simulation is the Cargo child-process boundary within the gate's own negative-control harness.

## 6. Failure model and gauntlet

P0 is Tier 3 because ambiguous future durable/public contract choices can make recovery unsafe. Its failure model is: contract drift or unsupported schema accepted; noncanonical hashing creates evidence mismatch; unknown config quietly changes behavior; a fixture encodes a false recovery oracle; a phase checker passes while running no test/an ignored test; a dependency/toolchain mismatch prevents clone reproducibility; or the CI declaration diverges from the local gate.

Required layers after the final edit:

1. `cargo fmt --all -- --check`.
2. `cargo clippy --workspace --all-targets --locked -- -D warnings`.
3. `cargo test --workspace --all-targets --locked`, then exact P0 target discovery/execution.
4. `pwsh -NoProfile -File scripts/Verify-Phase.ps1 -Phase P0` and `pwsh -NoProfile -File scripts/Verify-Docs.ps1 -SelfTest`.
5. A manual mutation pass against at least five meaningful defences (ID validation, version validation, canonical hash, config rejection, fixture/gate failure); each selected mutant must fail a relevant real test/gate, then be restored.
6. A real no-credential CLI invocation. CI may be declared but cannot be claimed locally run before GitHub executes it; committing/pushing is out of scope.

The initial repository has no coverage or off-the-shelf mutation tool. Installing either is intentionally deferred rather than silently adding global tooling; manual mutations are P0's replacement and the lower assurance is stated in evidence. Dependency vulnerability scanning is also skipped because no approved local audit tool exists.

## 8. Verification/restart handoff contract

Evidence identifies base and tested source state, changed files, contract/dependency changes, P0-F mapping, exact commands/results, platform/toolchain, manual mutation results, skipped layers, CI state (`not requested / unverified locally` unless a real CI result exists), limitations, and next safe action. Both handoffs list completed P0-S01..S07, file fingerprints, exact restart commands, and the only safe successor: request P0 acceptance before assigning P1.
