## 1. Goal / non-goals

**Goal:** nối vào TurnDriver/RuntimeService/store hiện có: (a) run/step/attempt/frozen request bền vững với ranh giới reserve+freeze atomic; (b) question/steering/cancel port cho human input, pause không giữ compute permit, answer dedupe theo scope/expiry; (c) budget reservation/settlement bền vững, checked arithmetic, loop detection và typed caps; (d) goal/terminal evaluator với typed criteria, acceptance tách khỏi run status, bounded continuation; CLI mock profile rõ ràng, status/resume đọc từ store.

**Non-goals (đúng runbook M3):** không real shell/file edit (fixture ToolExecutor qua cùng policy/approval/receipt gate), không history search, memory tables mới, workers/children; không tạo driver/workspace/CLI thứ hai; không real approval consume (M4 hoàn tất A11); không đổi data home, config, JSON cũ.

## 5. Contracts chốt cho M3 (defaults áp dụng)

- **IDs:** UUIDv7 typed sẵn có (`RunId` mới = chuỗi host-issued; dùng typed UUID mới trong `harness-types::ids`? — không thêm vào schema P0; dùng `harness_types::AgentRunId` cho run và `String` step id UUIDv7 nội bộ store, expose typed `RunStepId` ở harness-types nếu rẻ). Quyết định: thêm `RunId`, `RunStepId`, `QuestionId`, `BudgetId`, `ReservationId` vào `harness-types/src/ids.rs` theo đúng macro hiện có (không đổi schema P0).
- **Run states:** `running | waiting_input | completed | failed | canceled` (waiting_input = pause bền vững, không giữ permit).
- **Stop reasons (typed, persist):** `final | needs_input | external_wait | no_progress | loop_detected | step_limit | tool_limit | deadline | budget_exhausted | canceled`.
- **Acceptance:** `not_evaluated | satisfied | needs_work | needs_input | external_wait | unverified | rejected`; JSON CLI tách `run.status` và `acceptance`.
- **Question:** `(scope_key)` unique; scope_key = `run_id|request_id`; answer one-shot; cùng payload → trả kết quả cũ; khác payload → `IdempotencyConflict`; hết hạn → `ApprovalStale`; empty answer → `InvalidPayload`.
- **Budget:** `reserve(account, operation_id, origin, upper_bound)` unique `operation_id`; `settle(reservation, measured)` idempotent; unknown usage giữ bound; mọi phép cộng `checked_add`, tràn → `BudgetExhausted`; account cha tính tổng.
- **Loop detection:** cửa sổ N=6 signature `(tool_name, args_hash)`; ≥3 lần trong cửa sổ mà progress signature không đổi → `NoProgress`; signature trùng liên tiếp ≥4 → `LoopDetected`. Polling hợp lệ (args khác nhau hoặc progress đổi) không bị chặn.
- **Compatibility:** `RUNTIME_SCHEMA_VERSION` 1→2; DDL chỉ additive (`CREATE TABLE IF NOT EXISTS`); DB v1 tự nâng cấp khi mở writer; DB v2 bị host cũ từ chối (`MigrationFailed`) — đúng contract. Cập nhật assertion version ở `phase_p2::p2_s01` và `phase_p7::p7_writer_options_open_a_fresh_directory` kèm test nâng cấp v1→v2.
- **Không thêm ErrorCode mới** (schemas P0 giữ nguyên).

## 6. Invariants / failure modes

1. Một user input → một InputId; mọi step dùng `continue_run`, không admit lại.
2. Reserve+freeze nằm cùng transaction với step record; store lỗi → không dispatch provider/tool.
3. Question pause trả quyền điều khiển; không giữ SQLite transaction/await model.
4. Answer sai scope/ID không tìm thấy; không tự approve; empty/expired không thành consent.
5. Cancel ở boundary: queue chưa tiêu thụ không invoke fixture; trạng thái chưa rõ giữ `waiting`/`outcome_unknown`, không auto-rerun.
6. Budget không double count khi settle lặp; usage thiếu giữ conservative bound.
7. Model prose không tạo accepted; criteria cần evidence; evaluator lỗi → `unverified`.
8. Không loop trong CLI; goal continuation nằm trong TurnDriver/runtime.
