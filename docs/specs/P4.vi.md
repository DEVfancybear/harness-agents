# Đặc tả triển khai P4 — memory tái sử dụng và extraction phục hồi được

[English](P4.en.md) | Tiếng Việt

Trạng thái: **đặc tả triển khai đang hiệu lực**. SPEC này chỉ cấp quyền cho
P4-S01 đến P4-S07 và sửa ổn định gate P3 nếu cần để xác minh prerequisite.
Không cấp quyền cho P5 multi-agent, P6 external plugins, P7 delete/backup/release
hoặc P8 Web UI. Assignment P4 ban đầu và xác nhận tiếp tục của user cho phép
autonomous implementation; không có vòng phê duyệt riêng sau khi file SPEC này
được viết, nên evidence phải ghi rõ giới hạn tương quan đó.

## 1. Prerequisite và source boundary

Checkout trước P4 sạch tại `c9bb106cce67c5f0b7e3c02fafe1484e5f69d379`, trùng
`origin/master`. Evidence/handoff P3 được đối chiếu với source. Lần đầu chạy
`Verify-Phase.ps1 -Phase P3 -Json` gặp một failure timing ở test process P3;
ba lần chạy riêng test và ba lần chạy toàn target P3 sau đó đều pass. Full gate
P3 mới nhất pass với 15/15 required tests, regressions P0/P1/P2 và digest
`sha256:6ba31afe3d84ac2f0b0db340f1d861398f36d1bd2aa7514dbadf430e8b2492da`.
Không sửa P3 khi failure không tái hiện; dao động ban đầu phải xuất hiện trong
evidence cuối và full regressions phải pass lại sau source edit cuối.

P4 bảo toàn schema/ID version 1, single SQLite writer và host fencing, journal và
WorkingState là authority phục hồi, frozen request/context P2, policy/receipt P3,
và nguyên tắc optional memory không chặn coding resume.

## 2. Scope và kiến trúc được chọn

- Tạo `harness-memory` làm owner của memory contracts, publication policy,
  extraction/retrieval/invalidation services và mock external boundaries xác định.
- Mở rộng `harness-store-sqlite` bằng memory schema revision riêng. Mọi asset,
  version, grant, binding, dependency, job và cursor write đi qua coordinator và
  host fence hiện có; không tạo database authority thứ hai.
- Mở rộng runtime/context composition chỉ bằng proposed optional blocks và exact
  memory version refs. `ContextBuilder` P2 vẫn là component duy nhất admission,
  budget, ordering và freeze context.
- Mở rộng CLI bằng `memory search/read/inspect/invalidate/jobs/catch-up`; principal
  và scope được host dựng từ các option đã validate, không nhận authority nằm trong
  model payload.
- Mở rộng registry, phase verifier và CI matrix từ P0–P3 sang P4. Dừng trước P5.

FTS5/BM25 SQLite là baseline. Vector adapter chỉ là optional boundary để chứng
minh degradation; không nhận hỗ trợ vector production. L3 chỉ active khi có xác
nhận user/manual publication. Physical purge, Tencent/Redis/vector database,
daemon, embeddings thật và network calls nằm ngoài scope.

## 3. Contracts dữ liệu và policy

1. `MemoryPrincipal` do host cấp chứa principal cùng project/task/profile/session
   scopes. Search, read-by-id, inspect/export, publish, bind và invalidate đều kiểm
   tra action + object scope; identity trong request/extractor output không có quyền.
2. Asset có immutable versions và current pointer CAS. Status
   `candidate|active|superseded|invalidated|archived` tách khỏi validity
   `valid|stale|unknown`. Confidence chỉ ranking annotation, không thay authority.
3. Publication: runtime observation có source đã validate có thể active theo
   policy; model inference giữ candidate; decision user có thể supersede version
   cũ; profile L3 cần `SourceAuthority::User` và thao tác publish explicit.
4. Source batch bất biến gồm stream, inclusive sequence range, ordered source IDs,
   payload hashes, extractor version và strategy digest. Jobs đi
   `pending -> leased -> completed|retry_wait|blocked|paused|dead_letter`; lease
   generation cũ không settle được.
5. Cursor key là `(source_stream, extractor_version, strategy_digest)` và chỉ biểu
   diễn contiguous sequence có disposition. `no_facts` tiến cursor; unavailable,
   invalid output và extraction error không tiến. Strategy mới cần replay start rõ.
6. Dependencies giữ transitive lineage event/file/asset-version. Injected context,
   extractor output hoặc derived summary không trở thành evidence độc lập.
7. Retrieval trả `found|empty|degraded|error`, áp scope trước top-k, query có
   parameter, normalized Unicode/không dấu/snake/camel identifiers, và giới hạn
   hit/token/time. Snapshot revision phải được recheck trước dispatch.
8. Budget memory tách riêng calls/source bytes/output bytes. Hết budget hoặc
   shutdown pause durable job; catch-up sau chỉ tiếp tục bằng budget mới hữu hạn.

## 4. Failure model Tier 3

| Failure mode | Phòng vệ/test |
|---|---|
| Forged actor/project hoặc hash lookup vượt scope | Host principal + grant/scope query trước LIMIT; C08 và negative direct-read/export. |
| Lost update hoặc last-write-wins | Transaction CAS expected version; ba concurrent proposals C07. |
| Crash giữa asset/job/cursor writes | Một settlement transaction + injected pre-commit fault; C12. |
| Range trùng, timestamp collision hoặc settle ngoài thứ tự | Ordered sequence ranges, immutable digest, contiguous cursor; C16/C17. |
| Worker stale hoặc extractor JSON/source refs giả | Lease generation + output validation; C12/C22. |
| Memory tự củng cố hoặc decision cũ quay lại | Transitive provenance/supersedes/invalidation; C09/C13/C20. |
| Optional service lỗi làm mất task | Resume chỉ journal/WorkingState; typed degradation C05/K02. |
| FTS injection hoặc tiếng Việt/code recall sai | Parameterized MATCH terms + normalized mirror/exact identifier fallback; C26. |
| Mandatory rule cạnh tranh top-k | P2 builder nhận rule mandatory riêng; C18/C19 strengthening. |
| Cache/request dùng revision đã revoke | Snapshot validation ngay trước dispatch; C20/K10. |
| Background cost vô hạn hoặc CLI thoát mất claim | Finite budget, bounded retries và durable pause; C30. |
| Secret/artifact leak | Không capture credential; scoped content only và P3 C29 regression strengthening. |

## 6. Test, RED/GREEN và gauntlet

Acceptance target dùng `SqliteStore`, session/runtime/context builder, FTS5 và CLI
binary thật trên temporary data directories. Chỉ extractor, vector/embedding
boundary và clock/cancellation boundary phù hợp được mock; không mock transaction,
authorization, FTS, context builder hay component đang kiểm chứng.

RED đầu tiên phải discovery target P4 rồi fail do API/behavior chưa có. Thực hiện
S01–S07 theo dependency và chạy target liên quan sau từng lát cắt. Gate cuối:

```powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --all-targets --locked
cargo test -p harness-cli --test phase_p4 --locked
pwsh -NoProfile -File scripts/Verify-Phase.ps1 -Phase P4 -Json
pwsh -NoProfile -File scripts/Verify-Docs.ps1 -SelfTest
```

Kiểm tra discovery không rỗng/ignored và regressions exact P0–P3. Chạy property
tests cho CAS/cursor/normalization nếu phù hợp, thử 3–5 manual mutants khi không có
mutation tool, negative controls cho gate và adversarial forged scopes/ranges.
Coverage/mutation/audit/platform thiếu phải ghi `skipped` hoặc gap đúng sự thật.

## 7. Setup, dependency và Git

Dependency trực tiếp mới duy nhất dự kiến:

- `unicode-normalization = 0.1.25` (`MIT OR Apache-2.0`), đã hiện diện trong
  `Cargo.lock` transitively; dùng NFKD để tạo normalized FTS terms tiếng Việt và
  identifiers mà không tự duy trì bảng Unicode thiếu sót.

Không cài tool hệ thống, credential, dịch vụ, database ngoài hoặc gọi API trả phí.
Các thay đổi dự kiến thuộc `crates/harness-memory`, additive store/runtime/CLI,
`tests/acceptance/registry.json`, `scripts/Verify-Phase.ps1`, CI phase matrix,
SPEC/evidence/handoff song ngữ. Giữ nguyên mọi thay đổi user không liên quan.
Assignment yêu cầu commit và push khi hoàn tất; chỉ stage path thuộc P4 sau final
gate, rồi xác minh remote SHA/CI thật. Local PASS không được nhận là publish/CI PASS.

## 9. Bổ sung chi tiết triển khai

Không đổi version package ngoài repo. Tái sử dụng dependencies workspace:
`harness-session` cho context contribution, `tokio-util` cancellation, `proptest`
cho properties normalization và `sqlx` trong acceptance tests để đếm rows read-only.
Bật feature `signal` của Tokio hiện có để CLI hủy extraction có kiểm soát.
Runtime nhận optional memory contribution, kiểm tra revision trước mỗi provider
attempt; P2 chỉ freeze version refs của blocks thực sự được nhận.

Publication thủ công và L2 merge/summary có source versions hoàn thiện interface
profile/semantic merge. Bootstrap/index bindings đóng góp tối đa tám records trong
2.000 tokens ước lượng. Source đổi sẽ invalidate derived assets nhiều tầng;
historic versions vẫn inspect được theo grants hiện hành.

Fixtures bổ sung kiểm tra thu hồi grant nhiều tầng, revoke giữa provider retries,
source changes/merges/bindings và hủy khi extraction đang chạy.
`Verify-P4Gauntlet.ps1` chạy năm manual mutants có execution receipt trong bản sao
source tạm, restored tests/properties, rồi phase gate cuối. Coverage, advisory scan
và independent agents là các lớp phải báo riêng, không suy diễn từ phase gate.

## 10. Hồi quy toàn vẹn cuối

Fixture source/binding yêu cầu binding ID do host cấp được lưu/đọc nguyên vẹn;
không được gán lại ID cho asset/principal khác. Fixture S05 sửa rendered text và
yêu cầu `InvalidHash` trước kiểm tra snapshot. Rendering seal riêng phát hiện sửa
đổi sau khi tạo contribution; đây là kiểm tra toàn vẹn, không phải isolation khỏi
code thù địch bất kỳ trong trusted host process.
