## 2. Outcome, boundary, and non-goals

P1 delivers the smallest local durable-continuation kernel:

- Input ACK occurs only after one SQLite transaction commits its inbox record,
  event, raw instruction evidence, task projection, and source-work marker.
- A later process opens the same data directory, validates a snapshot, and
  folds its committed journal tail without a model call or tool retry.
- One writable host owns the data directory; fenced generations and task leases
  reject stale or competing writers.
- A plugin kernel validates required composition, scopes lookup correctly,
  owns registrations/resources, drains lost providers, and shares ordered
  shutdown completion.
- The CLI exposes persisted metadata only: init, sessions list, status,
  plugins list, plugins inspect, and config explain.

P1 does **not** implement a model loop, context construction or compaction
(P2), coding tools/process execution (P3), memory extraction/FTS (P4),
multi-agent execution (P5), third-party plugin loading (P6), release work
(P7), or a Web UI (P8). Scripted child hosts are crash fixtures, not agents.

## 3. Accepted architecture and contracts

### 3.1 Crate ownership

P1 adds harness-store-sqlite, harness-session, and harness-kernel.
harness-types gains shared P1 IDs and stable machine-readable error codes
only. harness-session owns commands, deterministic event folding and recovery
views; it cannot bypass the store coordinator. harness-kernel owns graph,
scope, resource and shutdown rules; it does not own task semantics or SQLite
SQL. harness-cli is an adapter and hosts the phase test and fixture-only
child binary.

Use sqlx = 0.9.0 with Tokio and bundled SQLite, fs2 = 0.4.3 for a
cross-platform writer lock, and Tokio 1.53.1. tempfile = 3.27.0 and
proptest = 1.11.0 are test-only. These crates were checked through crates.io
and support Rust 1.97. No network, credential, model, or external plugin
boundary is introduced.

### 3.2 Durable store rules

SqliteStore::open_writer takes an exclusive lock file before migration or
write access. It uses a one-connection SQLite writer with foreign_keys=ON,
WAL, bounded busy timeout, and synchronous=FULL. open_read_only never
creates or migrates a database. Migration statements and their applied-version
row commit in one SQLite transaction.

The database stores migration history, host fencing epoch, sessions, task
leases, idempotent inbox records, ordered event envelopes, instruction ledger
rows, task projections/source-work markers, snapshots, immutable synthetic
receipts, artifact metadata, and persisted plugin manifests. Every write
verifies its host fence inside its transaction. A task lease is unique per
task and records both session and generation.

Stable outcomes include writer_locked, stale_writer, read_only_store,
sequence_conflict, idempotency_conflict, task_lease_conflict,
storage_write_failed, snapshot_corrupt, and unknown_critical_event. A
configured test fault aborts the real SQLite transaction before commit. It
does not mock the transaction engine or fill a user disk.

### 3.3 Session transaction and recovery rules

SessionService::admit_input receives a UUIDv7 input_id, actor authority,
expected next sequence, task/session IDs, workspace observation, and raw text.
For a new ID it writes the inbox row, input.admitted envelope, raw instruction
ledger, a valid minimal WorkingState, task projection and source-work marker in
one transaction. Text remains classification=unclassified; P1 requires no
model classification. A retry with the same ID/payload returns the original ACK
without another event; reusing an ID with a changed payload fails.

Snapshots contain schema version, through_seq, canonical-content hash and a
serialized recovery view. Artifact bytes are written to a temporary file,
flushed, atomically published, then referenced by a committed record. Recovery
validates the newest snapshot; a damaged snapshot is diagnosed and journal
replay is used. A corrupt journal or unknown continuity-critical event fails
closed with its sequence. A receipt after the newest snapshot folds exactly
once and P1 never schedules it for execution. Pending intent is uncertain,
not completed.

### 3.4 Kernel rules

Plugin descriptors contain implementation instance, scope, generation and
versioned required/provided service contracts. Missing/incompatible required
services, cycles and duplicate same-layer registrations fail before session
admission. An absent optional extractor is a defined degradation. Lookup walks
from current scope to ancestors; sibling-private registrations are invisible.
A disposer removes only its exact (instance, generation, registration_id).

Mount resources remain unpublished until initialization succeeds. A failed
mount cancels, shuts down and joins gathered resources before returning an
error. Losing a required provider blocks new dependent calls, invalidates old
leases, drains in-flight calls, records uncertainty for unsettled calls, then
releases dependents. Concurrent shutdown callers share one completion report;
consumers close before providers and the store closes last. Cleanup errors are
aggregated.

## 5. Acceptance mapping and negative controls

phase_p1 uses the real SQLite store, session service and kernel. A test may
control an outside clock/fault boundary, but never mocks the unit under test.

| Case | Exact evidence target |
|---|---|
| C01 | Kill child after durable input ACK; reopen finds exactly one logical input. |
| C02 | Kill child after synthetic receipt commit and before a later snapshot; recovery folds tail and schedules nothing. |
| C15 | Second process cannot obtain writer ownership; after takeover, old fence is rejected. |
| C21 | Injected admission/receipt write failure has no ACK and no committed event, receipt or sequence advance. |
| C24 | Two distinct sessions cannot hold one task lease. |
| K01–K07 | Invalid composition; optional extractor; rollback/join; nearest scope; exact undo; provider drain; racing ordered shutdown. |

Property checks cover duplicate-ID idempotency, snapshot-tail equivalence, and
exact registration undo. Negative controls corrupt a snapshot, append an
unknown critical event, open read-only against an uninitialized directory, and
force migration/write-boundary failure. The recovery demo has two completed
plan items and one remaining item; status derives from persisted evidence and
explicitly states that P1 has no execution runtime.

## 6. Gate, documentation, and handoff obligations

The P1 gate runs P0 regressions plus:

~~~powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --all-targets --locked
cargo test -p harness-cli --test phase_p1 --locked
pwsh -NoProfile -File scripts/Verify-Docs.ps1 -SelfTest
pwsh -NoProfile -File scripts/Verify-Phase.ps1 -Phase P1
~~~

Verify-Phase discovers all registry-required tests, rejects ignored tests,
runs negative controls, verifies P0 regression, and produces a source-tree
digest excluding only P1 evidence/handoff metadata. P0 stays valid after P1 by
requiring its own cases while permitting later cases only when their own
registry entries are implemented and required; it must not call P1 capability
P0 capability.

Completion requires bilingual P1 evidence and handoff files containing fresh
commands/results, source digest, test names, platform limits, known gaps and a
restart handoff. This specification includes no P2 work, commit, push,
publication, or deployment.
