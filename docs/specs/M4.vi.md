## 1. Goal / non-goals

**Goal:** hoàn tất tool gate trên nền P3 + M3: (a) grant bind invocation/task/session/principal/action/workspace/revisions, consume+intent atomic, receipt bất biến, `call_id` được bind; (b) filesystem/Git read/patch có stale/link/binary safeguards + dirty/base/result fingerprints; (c) process lifecycle có admission permit cancellation-aware, env allowlist + secret JIT, tree cleanup trung thực, output spool/artifact với preview/page/quota typed; (d) E2E repo thật: read→patch→test fail→patch→test pass→final, evidence gắn workspace digest, crash giữa receipt/checkpoint rồi resume không chạy lại.

**Non-goals (đúng runbook M4):** không quảng cáo sandbox; không auto git commit/push; không remote executor; không parallel mutating calls; không đổi P0/H contracts ngoài phần cần (schema receipt/tool table có version + compat test).

## 5. Contracts, schema, migrations

- **Tools schema v2** (`TOOLS_SCHEMA_VERSION=2`, additive):
  - `tool_approvals` + `session_id`, `task_id`, `invocation_id`, `call_id` (nullable);
  - `tool_intents` + `call_id` (nullable);
  - binding hash bao gồm các field mới → test A14 negative control (bỏ invocation khỏi hash phải fail).
- **P0 receipt**: `ToolExecutionReceipt.call_id: Option<String>` với `#[serde(default)]`, cập nhật `schemas/tool-execution-receipt.v1.schema.json` + fixture drift test. Không đổi semantic field cũ.
- **`ToolDescriptor`** (harness-tools): `{ id, revision, schema_digest, effect_class, capabilities }`; `coding_tool_descriptors()`; validate trong `prepare` (unknown/revision mismatch → typed deny).
- **`ProcessOutcome`** (harness-tools): thêm `artifact_id`, `captured_bytes`, `content_hash`, `truncated`, `preview_head/tail`, `cleanup_confirmed`; giữ field cũ để tương thích.
- **Migration/compat**: DB v1→v2 tools schema tự nâng cấp khi mở writer; test compat như M3 (upgrade + newer-than-host refuse).

## 6. Invariants / failure modes

1. Grant một lần: invocation/session/task khác → deny; expiry/revoke → deny; race hai consumer → chỉ một intent (CAS).
2. Không có side effect mà không có event/intent; settlement fail sau effect → `outcome_unknown`, không auto-rerun, reconcile ghi event mới.
3. Observer sau commit không sửa receipt.
4. Path policy ≠ sandbox: ghi host limitation trong ADR; recheck hash ngay trước write; link/junction escape denied.
5. Queued process cancel trước spawn → không marker, permit/drain sạch; cancel/timeout sau spawn → tree reaped theo backend, nếu không xác nhận thì receipt `uncertainty`, không claim `tree_cleanup_confirmed`.
6. Env con không có secret/helper ngoài allowlist + grant tường minh.
7. Output dài: memory không giữ full log; preview + artifact ref + captured length/hash; disk-full → typed error, không ref giả.
8. Final criteria chỉ satisfied khi check evidence khớp workspace digest cuối; model prose/counter không đủ.
9. Không commit/push code của fixture vào repo user; fixture dùng temp dir.

## 11. Test harness (đo được trong checkpoint M4-01)

- Host Windows này thỉnh thoảng refuse loopback connect ngay cả khi test chạy một mình trong closure (quan sát ở gate M4: closure-M2 fail `a06_missing_terminal_and_truncated_arguments_are_not_dispatchable` với "provider request failed: error sending request for url"). `milestone_m2::collect` được thêm retry có giới hạn (12 lần, backoff tới ~3.2 s) **chỉ** theo đúng chữ ký refusal đó; refusal không tới được fixture nên không tiêu thụ response đã script, mọi lỗi khác vẫn fail ngay. Đây là cùng pattern đã dùng ở `interactive_launch::LOOPBACK_ATTEMPTS`.
- Gate runner: bước `workspace-tests` retry **tối đa 3 lần nhưng chỉ khi output khớp chữ ký flake** (`error sending request for url` hoặc `credential file … could not be written/replaced`); lỗi khác ném lại ngay. Bước required-tests của milestone vẫn single-shot.
- Tổng đo được qua các gate M3/M4: 8 lần chạy, 7 lần đỏ vì flake host ở các suite khác nhau (mỗi suite xanh khi chạy riêng); 2 lần đỏ vì code thật (A06 malformed semantics, status vocabulary registry M0) đã sửa trong code chứ không dựa vào retry.
