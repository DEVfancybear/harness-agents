## 2. Outcome and boundary

P2 adds a single-agent runtime that can perform a keyless, deterministic model
loop through a provider interface, construct an explainable context packet,
freeze and persist every request before dispatch, compact repeatedly without
deleting raw history, and resume or replay after process/session restart.

The runtime is an application service; CLI commands only compose and present
it. Providers normalize messages, tool-call deltas, terminal stream events,
capabilities, cancellation, and bounded retry outcomes. The DeepSeek adapter is
OpenAI-compatible HTTP/SSE with a host-resolved credential that is never stored
in requests, packets, events, logs, or snapshots. Tests use a local HTTP fixture
or an in-memory provider; no live credential or paid API call is required.

Mandatory context is assembled outside optional retrieval: system policy,
current user/project instructions (including `unclassified` text), objective,
acceptance criteria, current decisions and supersessions, WorkingState,
unsettled tool pairs, and the relevant recent tail. Optional contributors are
budgeted only after mandatory blocks. If mandatory content cannot fit after
output reservation, protocol overhead, and safety margin, the runtime pauses
with a typed explanation rather than dropping requirements.

Compaction writes a start marker, builds a candidate outside the SQL
transaction, validates mandatory coverage, and commits a checkpoint with CAS.
Tail changes cause retry/rebase; summary/provider failure uses a deterministic
WorkingState + event-tail fallback. Raw events remain durable. Context packets
and composition snapshots contain exact rendered content, ordered source
references, versions, non-secret effective configuration, and hashes.

Resume restores state and ownership without automatically repeating an uncertain
side effect. A new session may continue a task only after the stale prior
lease is safe to take over. Offline replay reads frozen packets and diagnostics
only: it dispatches no model, network, or tool call. Unknown critical events or
unsupported projector/composition versions block execution resume but still
permit read-only inspection of stored packets/history.

## 3. Failure model and non-negotiable invariants

| Failure mode | Required defence and evidence |
|---|---|
| Invalid actor/turn transition or duplicate command | Typed state machine rejects the transition; durable command IDs are idempotent and claims have bounded attempts. |
| Provider chunk split, malformed JSON, incomplete tool arguments, transport failure, or cancellation | Incremental SSE decoder returns normalized events/errors; incomplete tool calls are never executable; cancellation is observed and retries are bounded. |
| Credential leakage | Resolver supplies a secret only at outbound adapter call; persisted request/packet/attempt JSON is sanitized and tests scan it. |
| Mandatory context omitted or over budget | Ordered mandatory admission is independent of optional ranking; overflow returns a pause reason and no provider dispatch. |
| Config/context changes while a request is running | Composition and request are immutable records; a later revision applies only at a new step boundary. |
| Summary failure, stale compaction CAS, or repeated compaction | Deterministic fallback, CAS conflict handling, raw journal retention, and five-compaction property coverage. |
| Crash/reopen, stale task lease, or unknown critical event | Durable recovery receipt, safe generation takeover, execution block with offline inspection, and no blind replay. |
| CLI accidentally becomes the runtime authority | Runtime tests call application services directly; CLI tests verify presentation only and all mutations go through the runtime/store boundary. |

## 5. Data and API decisions

1. Keep P0/P1 event and WorkingState schemas at version 1. Additive runtime
   tables track a separately named runtime schema revision; no existing row is
   reinterpreted.
2. `ModelProvider`, `CredentialResolver`, context builder, and runtime service
   use object-safe boxed futures or synchronous validation plus boxed async
   calls. No Rust ABI or dynamic native plugin boundary is introduced.
3. Provider requests contain normalized roles/messages/tool schemas and a
   model capability snapshot. Provider-private fields are retained only under
   an explicit adapter namespace and are excluded from sanitized persistence
   unless a test proves they contain no credential.
4. `ContextPacket` content hash covers exact rendered UTF-8 content. Its source
   manifest and memory-version list are ordered and immutable. A frozen request
   references the packet/composition hashes and stores the sanitized request
   body actually dispatched.
5. Runtime events are non-tool, continuity-critical only when a decoder exists
   in this phase. Unknown critical events stop active resume; offline inspection
   returns the raw packet/history diagnostic.
6. Task takeover is permitted only when the previous task lease generation is
   stale after the prior writer has released ownership. Two sessions in one
   current host generation still conflict.

## 6. Setup and dependency authorization

Implementation uses existing Rust 1.97/Tokio/serde/sqlx stack plus these pinned
workspace dependencies:

- `tokio-util = 0.7.16`: cancellation tokens that propagate through runtime
  and provider calls.
- `reqwest = 0.12.24` with `json`, `stream`, and `rustls-tls`: HTTPS-capable
  DeepSeek HTTP/SSE adapter; tests point it only at a local fixture.
- `futures-util = 0.3.34`: consume the adapter's bounded response byte stream;
  this is compatible with the `sqlx 0.9.0` dependency range.

No credentials, external services, databases, or tools are installed or
activated. `Cargo.lock` records the exact resolved transitive set. The phase
acceptance target is `crates/harness-cli/tests/phase_p2.rs`; P2 source is owned
by `harness-runtime`, `harness-providers`, additive session/store modules, and
CLI composition.
