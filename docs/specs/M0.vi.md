## 1. Goal / non-goals

Goal: kiểm kê và chuẩn hóa contracts nền tảng trên source hiện có, biến chúng thành executable contracts (test chạy được, gate chạy được) mà không tạo workspace/CLI/runtime thứ hai:

1. M0-01 — typed IDs, `ScopeContext`, reducer `(state, command) -> (next state, events)`, `ErrorCode`/retry class, phân biệt run terminal / task accepted / human override.
2. M0-02 — port types theo CONTRACTS §3, versioned envelope + canonical serialization + golden fixture độc lập, dependency allowlist có negative control.
3. M0-03 — giữ root workspace/toolchain/`ha`, mở rộng config/CLI validation và JSON contract còn thiếu, thêm IdGenerator injection cho deterministic tests.
4. M0-04 — mapping A01–A36 trong `tests/acceptance/milestones.json`, gate `scripts/Verify-Milestone.ps1`, failpoint controller + child-fixture launch protocol test-only.

Non-goals (giữ nguyên ngoài scope M0): SQLite schema/migrations M1; provider protocol M2; TurnDriver loop M3; tool policy/executor M4; context compiler M5; skills/MCP M6; memory M7; multi-agent M8; backup/release M9; Web M10; daemon M11; strict backend M12. Không xóa bảng/cột/JSON field đang dùng; không đổi data home; không tạo crate mới; không chạy paid API; không commit/push.

## 5. Contract decisions (ADR-N01 — domain identity/state; dependency map; gate contract)

Ghi tại `docs/adr/ADR-N01-DOMAIN-IDENTITY-STATE.vi.md`; tóm tắt phần khóa implementation:

1. **Identity tách biệt:** `SessionId` = container hội thoại durable; `TaskId` = đơn vị acceptance; `AgentRunId` = một lần thực thi; `StepId` = một chu kỳ model/tool trong run (public ID từ M0, bảng thuộc M3). Ordering chỉ bằng `seq`/`SessionRevision`, không bằng ID hay timestamp.
2. **Ba state machine độc lập:** run (`AgentState`), acceptance (`AcceptanceRecord`), projection (`WorkingState`). Run terminal (`Completed/Failed/Canceled`) **không** tạo task accepted; human acceptance ghi `AcceptanceActor::Human{actor_id}` + `SourceRef`, không sửa criteria thành satisfied.
3. **Reducer thuần:** `(state, validated command) -> (next state, proposed events)`, terminal không regress (`InvalidStateTransition`).
4. **Lỗi:** `ErrorReport { schema_version, code, retry_class, safe_message, correlation_id?, details_ref? }` là contract JSON; `RetryClass` suy từ `ErrorCode`, không từ message.
5. **Dependency map:** allowlist khai báo trong `schemas/dependency-allowlist.v1.json`, kiểm bằng `dependency_check`; cấm `harness-runtime → harness-tools`, `harness-types → *`, mọi edge không khai báo.
6. **Gate contract:** `Verify-Milestone.ps1 -Milestone Mn` chạy `fmt/clippy/build/test/discovery` + dependency check + closure; required selector không tồn tại, ignored, hoặc 0 test đều **exit nonzero**; self-test có negative control.

## 7. Compatibility

- Không đổi schema SQLite, không migration, không đổi data directory/config path/JSON thành công.
- Lỗi vẫn ở stderr như mọi contract H/P đã accepted; khi `--json`, stderr là một JSON error document có version thay vì prose (prose giữ nguyên khi không `--json`). Đã kiểm bằng `p0_f02`, `p4_s07_cli_reviews_and_confirms_candidates_in_one_batch`, `i09_*`, `i12_*`, `i16_*`.
- Exit code lỗi đổi theo `ErrorCode::exit_code()` (2/3/4/5/130/1); fixture test khóa mapping; evidence ghi rõ đây là thay đổi có chủ đích theo CONTRACTS §9, không phải thay ngầm.
- `ErrorEnvelope`/`VersionedDocument`/`AcceptanceRecord` là type mới, không sửa chữ ký type đang persist. `EventEnvelope` không đổi field.
