# Đặc tả triển khai P1 — kernel và durable storage

[English](P1.en.md) | Tiếng Việt

Trạng thái: **đặc tả triển khai đang hiệu lực**. Hợp đồng này chỉ cho phép P1;
nó không cho phép P2 hay phase sau.

## 1. Uỷ quyền và bằng chứng tiền nhiệm

Yêu cầu trực tiếp thực hiện P1 là sự chấp nhận P0 minh thị mà handbook triển
khai yêu cầu. Đây không phải suy diễn từ tài liệu kế hoạch. Trước mọi chỉnh sửa
P1, baseline đã được xác minh như sau:

~~~text
HEAD / origin/master: bca9ed0413423621bb391880c06ab126c79b0765
pwsh -NoProfile -File scripts/Verify-Phase.ps1 -Phase P0 -Json: passed
P0 source digest: sha256:0edcf7d59d8c409ad1a76f9c4f88c92ec2a8e50c06baeb7ea4f187ccb3be7dc3
~~~

P0 gate mới này đã pass format, clippy, workspace tests, đủ tám P0 acceptance
tests, discovery và documentation checks. Các P0 contracts hiện hữu vẫn
version 1 và giữ nguyên ý nghĩa. P1 có thể thêm IDs, error codes và records do
SQLite sở hữu; không được diễn giải lại một P0 record hoặc nói fixture tĩnh P0
đã là runtime recovery.

## 2. Kết quả, ranh giới và việc không làm

P1 cung cấp kernel local nhỏ nhất để tiếp tục công việc bền vững:

- Input chỉ ACK sau khi một SQLite transaction commit inbox record, event, raw
  instruction evidence, task projection và source-work marker.
- Process sau mở cùng data directory, kiểm tra snapshot và fold journal tail đã
  commit mà không gọi model hoặc retry tool.
- Một writable host sở hữu data directory; fenced generations và task leases
  từ chối writers cũ hay cạnh tranh.
- Plugin kernel validate required composition, scoped lookup đúng, sở hữu
  registrations/resources, drain providers mất đi và chia sẻ shutdown completion
  có thứ tự.
- CLI chỉ hiển thị persisted metadata: init, sessions list, status, plugins
  list, plugins inspect và config explain.

P1 **không** làm model loop, context construction hoặc compaction (P2), coding
tools/process execution (P3), memory extraction/FTS (P4), multi-agent execution
(P5), third-party plugin loading (P6), release work (P7), hoặc Web UI (P8).
Scripted child hosts là crash fixtures, không phải agents.

## 3. Kiến trúc và hợp đồng đã chấp nhận

### 3.1 Sở hữu crate

P1 thêm harness-store-sqlite, harness-session và harness-kernel.
harness-types chỉ thêm P1 IDs dùng chung và machine-readable error codes ổn
định. harness-session sở hữu commands, event folding quyết định và recovery
views; không được bypass store coordinator. harness-kernel sở hữu graph, scope,
resource và shutdown rules; nó không sở hữu task semantics hay SQLite SQL.
harness-cli là adapter và giữ phase test cùng fixture-only child binary.

Dùng sqlx = 0.9.0 với Tokio và SQLite bundled, fs2 = 0.4.3 cho writer lock đa
nền tảng, và Tokio 1.53.1. tempfile = 3.27.0 cùng proptest = 1.11.0 chỉ dùng
cho test. Các crates này đã được kiểm tra qua crates.io và hỗ trợ Rust 1.97.
Không thêm network, credential, model hoặc external plugin boundary.

### 3.2 Quy tắc durable store

SqliteStore::open_writer lấy exclusive lock file trước migration hoặc quyền ghi.
Nó dùng một SQLite writer connection với foreign_keys=ON, WAL, busy timeout có
giới hạn và synchronous=FULL. open_read_only không tạo hoặc migrate database.
Migration statements và applied-version row commit trong một SQLite transaction.

Database lưu migration history, host fencing epoch, sessions, task leases,
idempotent inbox records, event envelopes có thứ tự, instruction ledger rows,
task projections/source-work markers, snapshots, immutable synthetic receipts,
artifact metadata và persisted plugin manifests. Mỗi write kiểm tra host fence
bên trong transaction. Task lease là duy nhất theo task và ghi cả session lẫn
generation.

Outcomes ổn định gồm writer_locked, stale_writer, read_only_store,
sequence_conflict, idempotency_conflict, task_lease_conflict,
storage_write_failed, snapshot_corrupt và unknown_critical_event. Fault do test
cấu hình abort SQLite transaction thật trước commit. Nó không mock transaction
engine hoặc lấp đầy disk của người dùng.

### 3.3 Quy tắc session transaction và recovery

SessionService::admit_input nhận UUIDv7 input_id, actor authority, expected next
sequence, task/session IDs, workspace observation và raw text. Với ID mới, nó
ghi inbox row, input.admitted envelope, raw instruction ledger, WorkingState tối
thiểu hợp lệ, task projection và source-work marker trong một transaction. Text
giữ classification=unclassified; P1 không cần model classification. Retry cùng
ID/payload trả ACK gốc mà không có event khác; dùng lại ID với payload đổi là
lỗi.

Snapshot có schema version, through_seq, canonical-content hash và recovery view
được serialize. Artifact bytes ghi vào temporary file, flush, publish atomic,
rồi mới được reference bởi committed record. Recovery validate snapshot mới nhất;
snapshot hỏng được chẩn đoán và journal replay được dùng. Journal hỏng hoặc
unknown continuity-critical event fail closed kèm sequence. Receipt sau snapshot
mới nhất được fold đúng một lần và P1 không schedule execution cho nó. Pending
intent là uncertain, không phải completed.

### 3.4 Quy tắc kernel

Plugin descriptors có implementation instance, scope, generation và versioned
required/provided service contracts. Required services thiếu/không tương thích,
cycles và duplicate same-layer registrations fail trước session admission.
Optional extractor vắng là degradation xác định. Lookup đi từ scope hiện tại
lên ancestors; sibling-private registrations không thấy được. Disposer chỉ gỡ
đúng (instance, generation, registration_id).

Mount resources chưa publish cho đến khi initialization thành công. Mount fail
phải cancel, shutdown và join gathered resources trước khi trả error. Mất
required provider chặn dependent calls mới, invalidate old leases, drain
in-flight calls, ghi uncertainty cho calls chưa settled, rồi release dependents.
Concurrent shutdown callers chia sẻ một completion report; consumers đóng trước
providers và store đóng cuối. Cleanup errors được gom lại.

## 5. Mapping acceptance và negative controls

phase_p1 dùng SQLite store, session service và kernel thật. Test có thể kiểm
soát outside clock/fault boundary, nhưng không bao giờ mock unit đang test.

| Case | Evidence target chính xác |
|---|---|
| C01 | Kill child sau durable input ACK; reopen tìm đúng một logical input. |
| C02 | Kill child sau synthetic receipt commit và trước snapshot sau đó; recovery fold tail và không schedule gì. |
| C15 | Process thứ hai không lấy được writer ownership; sau takeover, old fence bị từ chối. |
| C21 | Injected admission/receipt write failure không có ACK và không có committed event, receipt hay sequence advance. |
| C24 | Hai sessions khác nhau không thể giữ cùng một task lease. |
| K01–K07 | Invalid composition; optional extractor; rollback/join; nearest scope; exact undo; provider drain; racing ordered shutdown. |

Property checks bao phủ duplicate-ID idempotency, snapshot-tail equivalence và
registration undo chính xác. Negative controls làm snapshot hỏng, thêm unknown
critical event, open read-only với directory chưa khởi tạo và ép
migration/write-boundary failure. Recovery demo có hai completed plan items và
một remaining item; status lấy từ persisted evidence và nói rõ P1 chưa có
execution runtime.

## 6. Gate, tài liệu và bàn giao

P1 gate chạy P0 regressions cộng với:

~~~powershell
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --all-targets --locked
cargo test -p harness-cli --test phase_p1 --locked
pwsh -NoProfile -File scripts/Verify-Docs.ps1 -SelfTest
pwsh -NoProfile -File scripts/Verify-Phase.ps1 -Phase P1
~~~

Verify-Phase discover mọi registry-required tests, từ chối ignored tests, chạy
negative controls, verify P0 regression và tạo source-tree digest chỉ loại P1
evidence/handoff metadata. P0 vẫn đúng sau P1 bằng cách đòi cases của chính nó
và chỉ cho cases phase sau khi registry entry của chúng implemented + required;
nó không được gọi P1 capability là P0 capability.

Hoàn tất cần P1 evidence và handoff song ngữ có commands/results mới, source
digest, test names, platform limits, known gaps và restart handoff. Đặc tả này
không gồm P2, commit, push, publication hay deployment.
