# Live tests

End-to-end checks that drive a real `ha` against a real model, the way a user would: agents are started in a pseudo-console, sent messages with `ha send --wait`, restarted and resumed, and what they answered and what they left on disk is checked. Each check prints `PASS` or `FAIL`; the script ends with `RESULT: N passed, M failed` and exits non-zero on a failure. The conversation (`conversation.md`), the recordings and the state stay in `$LIVE_ROOT/<test>` as evidence.

They cost model calls and take minutes, so CI does not run them; run them before a release that touches what they cover.

## Running

```bash
cargo build --release -p harness-cli --bin ha --locked
cargo build -p harness-cli --example pty_probe --locked
export HA_CREDENTIALS_DIR="$LOCALAPPDATA/HarnessAgents/data/private"   # use credentials authorized for the test
export LIVE_ROOT="$TEMP/ha-live-release-check"                      # disposable evidence directory
export HA_CONFIG="C:/path/to/test-config.toml"                      # reviewed config copied into each test home
bash scripts/testing/live-tests/memory.sh
```

`env.sh` describes the variables (`HA`, `PROBE`, `PY`, `MODEL`, `THINKING`, `LIVE_ROOT`, `HA_CONFIG`); the defaults suit a Windows checkout with Git Bash. Set `MODEL` to a model your test credentials can call, and `THINKING` to its level; a release runs them with `MODEL=openai-codex/gpt-6-luna THINKING=max` ([`AGENTS.md`](../../../AGENTS.md)). Unset, `MODEL` is `opencode-go/deepseek-v4.1-flash` and `THINKING` is empty (the model's own default). `THINKING` is passed as `--thinking` wherever `--model` is. Each test copies `HA_CONFIG` into its own `HA_HOME` under `LIVE_ROOT`; inspect that config and its hooks before running. `fresh <name>` removes the existing `$LIVE_ROOT/<name>` directory, so save earlier evidence and never point `LIVE_ROOT` at user data. The agents run with `--approval full-auto`, use real credentials and make billable model calls; a disposable home is not a security sandbox.

`PY` must be a Python 3.11+ environment with the kernel's packages (the kernel venv's interpreter is one); `kernel.sh` also runs the REPL on it. `prime.sh`, `tui.sh` and `sidebar.sh` read recorded screens with `screen.py` (which adds the scroll commands pyte lacks), which needs `pyte` in that environment (`uv pip install --python "$PY" pyte`, or a `pylib/` beside it, or on `PYTHONPATH`). `tui.sh` prints a `SKIP` for the wheel checks when `PROBE_WT` is unset; that is not a wheel-test pass.

`session-continuity.sh` uses the supplied minimal `session-continuity-config/config.toml`, not your personal config. It makes eight app turns, disables automatic reviews and intentionally terminates only a checked isolated test worker after a response is durable. Use a fresh external `LIVE_ROOT`; set `HA`, `PROBE`, `PY`, `HA_CONFIG` to that config file, `HA_CREDENTIALS_DIR`, `MODEL` (the provider and model the config names; the supplied one names `openai-codex/gpt-6-luna`), `THINKING=max` and `LIVE_CONFIRM=session-continuity-billable` explicitly. A control on the previous binary should fail the four FEATURE recall checks, not the safety controls. The helper's synthetic, credential-free checks run with `python scripts/testing/live-tests/session-continuity-evidence-test.py`. A failed precondition exits 2 and invalidates the run; it is not a feature verdict.

These live checks supplement, not replace, the credential-free workspace and release-artifact checks in the [build and release guide](../../../docs/guides/BUILD_AND_RELEASE.md). The mock Python desktop regressions do not exercise the real Windows desktop; the [computer-use guide](../../../docs/guides/COMPUTER_USE.md) documents the separate opt-in smoke test.
